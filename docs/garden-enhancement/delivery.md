# 七步增强新版交付

本页说明第七步新版的文件与运行方式；具体候选、最终解压结果和签收状态以同名前缀的版本总清单及验收记录为准。本轮新增介绍完整羽化、水球曲面流纹、可接管自动导览、世界云影和三只风格化飞鸟，保留三柱内容和唯一场景/画布。

## 下载什么

新文件使用`garden-enhancement-step7-<构建指纹>`前缀，与旧`courtyard-*`、`portfolio-*`和`scroll-garden-step12-*`分开保存。

| 文件结尾 | 用途 |
| --- | --- |
| `-source.zip` | 可修改源码、锁文件、素材、构建配置、启动工具、当前说明及检查源码 |
| `-site.zip` | 最终HTML/assets及无额外npm依赖的本地预览工具 |
| `-evidence.zip` | 本轮报告、必要基线、原速演示与所引用的历史证据；不作为网页入口 |
| `-manifest.json` | 候选、工具链、三个ZIP的文件数/字节/SHA256与独立解压结果 |

每个ZIP有`PACKAGE-MANIFEST.json`，覆盖包内其余文件，排除自身避免哈希循环；外部总清单再核对ZIP。最终包核验报告和签收摘要在包外保存并由总清单引用。包内冻结的是候选与封包前检查，不能反过来包含自身最后生成的ZIP哈希。

源码不含node_modules或Git历史，构建依赖由lock固定；成品不需要安装npm依赖。两者均不包含凭据、浏览器用户目录或重复旧ZIP。验收附件如含历史来源会标识原候选；新旧报告不会混写成同一轮运行。

## 本机运行

Windows先安装Node LTS24。成品包完整解压后双击`START-PREVIEW.cmd`；源码日常修改双击`START-DEV.cmd`。脚本通过npm.cmd避免npm.ps1执行策略问题，中文/空格目录和端口占用有提示。启动Node服务的本地地址仅本机可用。

手动开发：`npm.cmd ci`、`npm.cmd run dev`。构建：`npm.cmd run build`，再`node scripts/preview-site.mjs`。macOS/Linux把npm.cmd换成npm。已用Node24.22.1/npm11.9.0验证，仓库最低Node22.12/npm10；完整步骤见[快速上手](quickstart.md)。

直接双击HTML的file://方式不作为运行入口。成品预览使用HTTP，无API密钥、数据库、应用后端或CDN依赖；首次安装源码依赖仍需要网络或已填充缓存。

## 静态托管

生产内容是成品包里的`index.html`、`assets`、favicon、分享图等文件。上传这些静态文件到支持正确JS模块MIME的主机即可；本地启动脚本、验收资料和源码不需要上传。

Vite使用`base: './'`，同一产物可放站点根目录或`/sakan/`这样的真实子目录。子目录访问地址应带末尾`/`。缺失JS、图片或媒体必须返回404，不用首页HTML假装成功。HTML建议no-cache，哈希assets可长期缓存；视频需能正常获取和播放，包内预览工具支持字节区间读取。

默认`./`进入当前庭院；`?tour=prototype`是旧收藏兼容入口；`?tour=reference`是原固定视角参考稿。普通访客无需debug或诊断参数。

目前未配置正式域名，canonical/og:url和分享图绝对HTTPS地址应在选定域名后填写，并按实际分享平台抓取验证。本地文件和HTTP检查不表示已上线或已被分享平台抓取。

## 独立核验与边界

交付时三个ZIP分别在空目录检查CRC、条目安全、SHA256和实际解压字节。源码在独立目录按锁文件安装后严格构建并核对最终成品；成品按自己的工具启动，并实际验证根路径、真实子路径、全部HTTP素材、正常/像素和关键阅读/作品操作。

当前Linux实际运行、桌面模拟、GTK WebKit和软件图形结果会分别记录。实体Windows双击、iOS/Android、硬件GPU FPS、地址栏/系统字体/安全区、VoiceOver/TalkBack、实体触控板/APZ仍按实际是否实测标记，不以桌面模拟冒充。

真实个人AI影片仍待用户提供，现有设计样片和早期12秒无声片段维持明确标识。内容替换位置见[维护说明](maintenance.md)。

最终交付会分别记录工作区、归档、Git提交、GitHub推送与网站发布状态。本步完成本地候选交付，远端同步和网站上线按照用户明确指令处理。
