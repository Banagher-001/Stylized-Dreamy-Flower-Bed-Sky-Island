# 第一步执行标准：基线与设计合同

本标准来自用户确认的七步方案和随后「细化第一步」「执行第一步」指示。目标是形成可以核对、比较和回退的基线，以及供第二至七步使用的具体设计、交互与验收合同；不将计划效果算作已经实现。

执行状态：第一步已完成，实际结果见[验收](step-1-verification.md)和该页引用的机器证明；第二步尚未执行。

## 执行顺序

1. 核对工作区、HEAD和GitHub main；用户后来加入的修改先识别保留，不用旧快照覆盖。保存实际提交、文件摘要和检查环境。
2. 对照现有构建证明，核对当前实际源码、锁文件、素材和dist。匹配时保留已核验构建；不匹配时先说明差异再建立正确候选，不能拿旧dist作为新源码结果。
3. 持久保存可独立解压的源码/成品基线，以及全部原有归档的字节数和SHA-256；保留旧ZIP原字节。
4. 从独立解压的基线采集开场、介绍三站、水潭、结尾和查看器代表画面。覆盖桌面/手机与正常/像素代表组合，另存介绍黑边及原速水球运动证据。
5. 记录真实正文、布局/资源及独立运行的原生滚动响应。标明软件图形、设备模拟及大字模拟的边界；历史证明只作明确引用。
6. 确定介绍雾幕、水球流纹、云影、三只鸟的初始视觉范围和保护项。
7. 确定自动导览的开始、停止、接管、继续、结束，及它与环境播放、作品层、稳定阅读、减少动态、隐藏/恢复的关系。
8. 形成逐站停留和转场表、未来验收场景与资源预算；核对文档间一致性。
9. 对照实施前摘要检查原有文件未变、基线可恢复、证据来源和状态真实，签收E01～E10。
10. 停在第一步审阅点；第二步另行细化并由用户明确开始。

## 保护与证据要求

保护三柱布局、色调、像素风格、原16段/12.3H、十个阅读站和五入口；保护原生滚动、魔法文字、正文选择、个人事实与素材来源、查看器返回、稳定阅读/大字/减少动态/图形失败时的阅读能力。具体保护范围和后续可改位置见[设计规范](step-1-design.md)。

真实截图、原速录像和设计描述分别标记。黑边、水球流动不足和缺少新功能是本次基线的已知现状，不能为了截图临时修CSS、换水球材质或隐藏问题。计数必须注明本步实测或历史继承，不重新跑无关的历史全套来凑数量。

第一步业务代码、素材、旧dist和旧交付包保持原样；允许新增本目录、独立证据目录与只读采样工具。当前源码与第十二步构建输入相同，但GitHub交接README和忽略规则晚于第十二步封包，二者不能冒充完全相同的源码包文档快照。
