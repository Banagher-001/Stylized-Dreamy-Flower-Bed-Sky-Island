## 接入原则

1. 保留原成品 HTML 和内部界面，通过本地同源路径的大尺寸 iframe 打开。
2. 主站承担作品选择、档案、载入反馈、独立打开和返回；原网页承担场景、控制台、模拟、截图和沙盒。
3. 主站不注入原页 CSS 或业务脚本，不用主站 Three.js 替换原引擎，不使用 WORLD_STUB 等开发替代场景。
4. 一个查看器同时只运行当前选择的作品。进入瓶中海洋时停止被覆盖主庭院的持续绘制，罗森实例退出；离开时释放瓶中海洋实例，再恢复阅读状态。
5. “不影响主站”落实为样式/脚本不串用、输入不误触、阅读/焦点正确恢复、资源不重复持有，以及既有罗森和庭院回归。具体设备性能按实测报告，不承诺所有设备零开销。

## 第一步：建立原版功能基线

固定原仓库提交和成品 SHA，在独立 HTTP 页面核查实际加载、错误、控制与效果，整理功能矩阵和原有局限。

必查：

- 12 个滑杆：波高、波速、密度、方向、水位、船体响应、阻尼、风力、像素强度、夕阳、亮度、瓶身透明度。
- 3 档画质、5 个镜头、灯塔/浪花/沙尘开关。
- 拖动、平移、滚轮、瓶子/地形双击、灯塔点击。
- 播放/暂停、参数重置、镜头恢复、面板折叠、UI 隐藏与恢复。
- 石头/贝壳放置、撤销、恢复装饰、退出编辑。
- H、Space、Escape 的原行为与焦点条件；截图按钮实际导出的 PNG。
- 真实水面变化和船体浮沉/俯仰/横摇，区分“数值改变”与场景联动。

验收：原页正常项、原页已有问题、设备限制、未验证分别记录；原 QA 只提供线索，不替代本轮实际结果。截图按实际成品的画布 CSS 尺寸 × min(DPR,2) 导出场景 PNG；1920×1080 是原报告的一种测试条件，不是所有情况下的固定输出，不误称包含 DOM 面板。第一步详见 [执行标准](step-1-standard.md)。

产物：文件清单、功能矩阵、原页截图/日志、原版问题和后续接入信号。

## 第二步：明确隔离、状态和资源归属

审查当前查看器中只识别 LAWSON 的判断，为第二个独立网页规定项目身份、入口、状态观察、重试、卸载、焦点与阅读恢复接口。

瓶中海洋使用自己的就绪/错误与 canvas 信号，罗森继续按原信号判断。不能将 iframe load 或 HTML 加载成功直接算场景就绪。普通浏览器标签切换保持原实例；关闭或离开现场后的重开规则与原网页重新打开一致。

验收：明确只有一个活动作品实例，旧回调不覆盖新作品；原页内部 H/Space/Esc 和宿主关闭分工清楚；不为接入默改默认参数、模拟时钟或原交互。

产物：查看器状态表、每个实例的生命周期与最小修改范围。

## 第三步：保存独立运行文件

按固定原版本保存成品与第三方声明，规划路径如 public/experiments/bottle-ocean/index.html。封面优先使用真实原场景截图；记录来源和尺寸。成品直接随主站 public 构建复制，不把原工程依赖加入主站，也不默认重构建原成品。

验收：原/公有目录/构建中的成品 SHA 一致；根路径和项目子路径下能独立打开，必要内容完整，运行不依赖 GitHub 在线加载。主站尚未进入该作品时不加载其 3D 运行页。

产物：可独立访问的完整网页、运行文件清单、来源说明。

## 第四步：扩展 Coding 作品入口与档案

现有 LAWSON、COURTYARD 加入 BOTTLE OCEAN，展示名使用「瓶中海洋」。沿用现有 Coding 区与作品查看器；选择项、当前封面、介绍、档案和独立链接绑定同一个项目身份。

封面呈现真实瓶中帆船，档案围绕「海浪与船体联动」「像素海岸」「沙盒与镜头」组织。补齐桌面/小屏布局和三作品键盘选择，避免依赖旧的双选项左右切换逻辑。

验收：新增作品可发现、身份清楚；三种作品的标题、封面、按钮和内容不串用；石柱阅读空间、原有作品入口、水潭进入庭院的归属保持正确。

产物：第三个作品入口、真实封面和独立档案；本步不把入口可见等同完整接入验收。

## 第五步：接通完整网页的大尺寸现场

在共享查看器中按需创建瓶中海洋 iframe，让原网页占据工具栏以外的可用区域，保留原品牌、控制台、像素渲染和全部内部操作。

接通 loading/ready/slow/error、重试和独立打开。读取当前原文档的真实状态，处理新文档、失败及图形丢失；不信任旧文档或旧 GPU 状态的 ready。截图下载保留真实用户手势和原导出行为，不能因容器权限或遮罩失效。

关闭/档案切换/项目切换时卸载旧实例，取消宿主计时器和监听，停止旧文档回调。当前作品打开时主庭院按既有规则暂停，退出恢复原阅读锚点、焦点与用户播放选择，导览不自行续播。

验收：完整场景可进入、可操作、可退出；大尺寸画布不拉伸、不以截图代替；退出后没有遗留 iframe/动效或滚动锁。

## 第六步：检查主站隔离、异常与兼容

重点组合：

- 原页滚轮缩放/拖动/快捷键，不改变主站滚动进度或导览。
- 原页 H 只控制原页 UI；原页 Escape 退出放置模式，宿主工具栏焦点 Escape 才按宿主关闭规则处理。
- 原页截图实际下载；编辑、撤销、恢复、暂停和重新进入按原规则运行。
- 载入中关闭、重试后切档案、三作品来回切换和反复开关。
- 小屏面板展开/折叠、横竖屏/窗口改变、慢载入、错误页和 WebGL 故障。
- 罗森现场与重试、庭院正常/像素模式和媒体、主站关于我/影像/石柱运镜及自动导览代表回归。

验收：最多一个独立网页实例；无误报就绪、串项目状态、抢焦点、残留遮罩或丢失阅读位置。分别记录 Chromium、Firefox、WebKit 的实际范围，手机模拟和真机分开。

## 第七步：原页／内嵌最终对照与交付

同浏览器、同子文档尺寸及相同前置状态，逐项对照第一步的原功能矩阵。真实操作后观察场景或导出效果，不能只比较控件数量。

完成构建、源文件完整性与 HTTP 访问验证；产物包含完整瓶中海洋网页、更新主站源码、运行说明、已知问题和验收记录。已有八组历史封存保持，只为本次建立新记录。

验收：原页正常项在内嵌中保留，主站新增阻塞问题清零，原有问题和未验证条件如实列明；只有入口、完整操作、返回、异常恢复及既有作品回归都完成，才认定接入完成。

第一步结果见 [验收报告](step-1-verification.md)。其余步骤按用户指示逐步细化与实施，不提前将整套接入写成已完成，也不因原仓库 README 的 Pages 说明而自动部署。
