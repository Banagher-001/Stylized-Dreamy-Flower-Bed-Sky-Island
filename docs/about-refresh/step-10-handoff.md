# 关于我改版 · 第十步交接

第十步完成全文预览、点击固定、收起及输入协调。下一步是第十一步的卡片飞离，需要先细化并获得用户执行指示。本步保持清新花园与石牌风格，未提交、推送或发布。

[实现说明](step-10-details.md) · [验收](step-10-verification.md)

## 当前接口与所有权

- `ToolCardView.setPose` 仍负责基础轨道/飞入姿态；`setReading` 组合阅读平移、深度、缩放及鼠标倾角，不直接争写同一个 transform。
- `setDetail(mode, width?, reveal?)` 管理 summary / preview / pinned / catalog、实际宽度、同一份正文、按钮和十面实体。`probeDetail` 同步探测最终全文尺寸，探测期间不把内容暴露给辅助技术，不发用户交互或布局通知。
- `createCardHover` 持有唯一阅读状态与一个按需 RAF。固定目标 `wantedPin` 通过 `pinnedChanged` 写入 `CardsSnapshot.expandedId`；临时预览不写快照。
- `createCardTrack.holdReading` 临时冻结轨道，保留用户的自动选择；程序轨道尚未绑定时也可以先持有。`step(direction, fromId)` 以实际阅读卡为邻接起点。
- `nativePinned` 清除旧程序位置，按固定 ID 对齐原生轨道；异步位置恢复也优先固定 ID，避免手机上固定内容在可视范围外。

## 第十一步必须承接的约束

1. 先保存分类、固定 ID、位置、方向及最新自动选择，再把阅读呈现交给飞离。临时预览清理，固定选择可恢复；不要保存旧鼠标角度或中间宽度。
2. 一张工具仍只有一个真实节点、一份正文和原生按钮。飞离不可使用复制卡冒充实际内容，也不增加新的 Three 渲染器。
3. 飞入仍由 `createCardEntrance` 管理首次四张实体。飞离与阅读、轨道要有明确交接，不能同时修改卡宽、基础姿态、阅读深度和父级归属。
4. 阅读时普通 232/240 px 槽位中的实体展开至 340/360 px，实际自然高度约 306 px。飞离测量必须包含实际全文宽高、十个面和阴影三倍模糊范围，不能复用普通 232×300 的预算。
5. 卡排占位维持 18.75rem；这避免悬停正文出现触发主站容量重测与相机模式切换。飞离同样不要逐帧请求全页容量测量。
6. 临时详情正常收起：正文先淡出 100 ms，随后收宽 200 ms；几何回到紧凑形态才释放 hold。飞离可显式接管该 hold，但不可让轨道先动、阅读层再回位。
7. 预览中的第一个合格滚轮事件先直接收束阅读，再把同一事件交给横向输入。固定阅读中的滚轮交还页面；继续自动展示则先收牌、再恢复运动。这些规则不能被飞离动画阻塞。
8. pointerdown 冻结宽度、正文进度与姿态到原生 click 分发。预览转固定不关闭重开，固定后移开鼠标仍保留；收起或 Escape 抑制当前位置立刻再次预览。
9. 序号跟随当前阅读 ID，上一张/下一张以阅读 ID 为起点，固定切换后继续固定。不要改回用轨道最左卡作为阅读序号。
10. 全部工具静态呈现 22 份全文；返回恢复分类、固定 ID、位置及返回入口焦点。章节往返、重挂和快照同样恢复固定内容；恢复过程不发送用户交互去停止主导览。
11. 程序轨道共享三维空间，阅读深度抵消边缘牌负 Z；原生轨道中的卡拥有各自的局部透视，宽阅读卡必须保留高于相邻卡的堆叠层级。最后视觉复核查出的遮挡已用原生命中网格覆盖，后续不能只检查 DOMRect 没有溢出。
12. 手机、窄窗、大字和减少动态采用原生全文阅读，无需先悬停；允许页面自然滚动。缩放、后台、章节离开、媒体变化和销毁清理临时状态、候选、定时器和 RAF。
13. 资料、22 张卡的正文/排序/图标继续复用；不增加项目或奖项，不影响 AI 影像、罗森、漂流瓶与花园环境播放选择。

第十步所有原始开发运行与最终采纳结果均保留在 `evidence/step-10`，不要覆盖前十步档案。下一步开始前建立新基线，执行后按实际运行记录验收；开发用 `npm run dev`，构建用 `npm run build`。
