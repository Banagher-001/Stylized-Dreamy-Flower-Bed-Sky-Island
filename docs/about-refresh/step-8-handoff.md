# 关于我改版 · 第八步交接

本步实现滚轮速度、方向与缓冲，下一步仍需用户先细化并授权执行。未提前实现悬停放大、鼠标倾斜、详情新编排或飞离，也未提交、推送或发布。

[实现说明](step-8-wheel.md) · [验收](step-8-verification.md)

## 当前接口

`createCardTrack` 继续拥有唯一横移时钟、逻辑相位、循环周期和空间弧度。新增 `wheel(delta, now?)`、`wheelAvailable`、`releaseWheel()`；`pause()` 立即清除基础速度及输入尾段。滚轮可在自动选择关闭的程序轨道中启动同一个时钟，停止输入后自行取消帧。基础展示开启时，停止输入后按最近方向以 28 px/s 继续。

`cardWheelInput.ts` 只有归一化、手势轴归属与近期目标计算，不创建监听、计时器或帧循环。`createToolBrowser` 的唯一 rail wheel 监听决定所有权；纵向归属会阻止页面默认滚动并通知主导览交还控制，却不调用会暂停卡牌的通用 `interact()`。横向手势仍归原生浏览器，首个交接事件只转移一次。

快照新增可选 `direction`、`leadIn`，兼容旧快照；保存当前卡 ID 与带符号 offsetRatio。恢复不保存或追赶速度。尚未绑定轨道时再次 capture，也保留 saved 中的弧度与首次接缝准备信息。销毁后的旧控制器不会因 clearCardViews 再次改成 paused。

## 第九步前需处理的视觉细节

本步录像和 1920 px 静帧中，边缘浅角度牌面仍可看到既有阴影的局部矩形交叠。当前 `.ar-card-shadow` 位于 position 层，和 reading 层同处共享 3D 空间；后续悬停姿态合成时应让阴影始终处在实体后方，复查面、厚度、阴影的深度顺序，再按放大后的真实投影调整循环换位预算。本步保持前一步材质 CSS，不将该既有分层外观记作滚轮逻辑缺陷或已修复事项。

## 第九步必须保留

1. `setPose` 目前由轨道写入基础 yaw（边缘至约 ±6°）。悬停层需要与轨道基础姿态合成，或使用现有 reading/orientation 分层；不得独立争写同一 transform。
2. 指针点击前先停运动，只有 `:focus-visible` 的键盘焦点才自动对齐。局部露出的卡牌按钮仍必须第一次原生点击就生效。自动展示按钮的 focus/Enter 不得被通用暂停监听抵消。
3. 透明的 stage、slot、实体根都保持 pointer-events:none，真实前牌面接收 pointer-events:auto。否则后方卡牌会被透明的 3D 外框挡住。
4. 暂停、切类、展开详情、全部工具、离开 A3、后台、布局、尺寸、减少动态与销毁都要清空输入尾段。恢复只用位置、方向、用户选择，不重放旧惯性。
5. 循环仅换位离屏节点，不复制卡牌，不改变 DOM 或数据排序。初始反向前有离屏余量，安全后移除。悬停增加空间尺寸后必须重新核对真实牌面与阴影的安全边界，不能继续盲用当前 64/40 px 预算。
6. 滚轮捕获范围是 rail 的真实矩形。标题、分类、按钮、继续阅读区域与不支持布局保留页面滚动。缩放修饰键不接管；横向手势保持原生，不叠加浏览器已有惯性。
7. 弧度独立于速度起动；暂停或继续不能让曲轨再次被拉平。自动开关与主场景播放、主导览相互独立。
8. 主站容量测量不触发飞入或轨道。真正 A3 重新可读、相机 settled 后才恢复；稳定模式底边界用视口，沉浸模式扣除固定底栏。
9. 仍只有一个可访问的 HTML 正面，每工具一个真实节点。用户资料、22 张卡正文、默认及分类顺序、本地图标和 Coding 嵌入功能不变。

运行仍是 `npm run dev`；生产构建是 `npm run build`。新工作先建下一步基线，不覆盖 `evidence/step-8/` 或此前档案。所有临时浏览器与验收服务在本步交付前关闭，具体记录见验收文档。
