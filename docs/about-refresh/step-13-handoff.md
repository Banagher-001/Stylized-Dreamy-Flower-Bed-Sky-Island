## 本步新增的衔接约束

- createCardHover.setTouchInput：触摸时停止沿用鼠标预览与倾斜，固定内容转为原生全文；实际鼠标或键盘输入可恢复相应呈现。available 提供实际悬停可用判断，说明复用它。
- createToolBrowser：触摸按住卡片按钮时只暂停，保留原生 click 的真实目标；点击后再交接。超过 8 px 转为手势，未点击的 pointerup 有一次 350 ms 兜底。取消、状态恢复、布局失去能力、内容重建及销毁都应释放持有。不得用合成 click 或卡片克隆替代。鼠标移动的输入识别在捕获阶段，先于卡排悬停判定；不要改回冒泡阶段导致首次停留失效。
- createReadingLayout：工具区触摸与原生滚动期间，推迟仅由内容变化触发的容量探测。滚动安静 160 ms 后交给原有 120 ms 调度；视口和字号变化可优先测量。forcePending 合并未执行的强制请求，不能在延迟时丢掉字体/内容变化。后台等待，销毁清理。
- startTourPrototype.rendererState：restored 表示连接已恢复，ready 表示首帧已绘制。连接恢复就结束旧超时与中断提示，屏幕外画布等待可见再绘制。不能为了刷新提示强制滚回封面、开启环境或重启导览。

## 继续保护

个人资料、22 张卡正文与图标、分类顺序、原有作品资源保持。每工具一个真实实体，布局切换不重新创建整排。首批入场不重播。固定对象、分类、有效位置和可达焦点继续保留；瞬时指针、惯性、帮助与未结束飞行不当作长期快照恢复。

说明仍位于三维链外，开启时只临时持有暂停；关闭只释放自己的持有。固定阅读 Escape 优先级、全量工具返回、首次外部点击保持。自动卡排、主站导览与环境播放分别管理，用户主动暂停不得被旧回调覆盖。

容量以实际字体、按钮和安全区域判断。不同浏览器可能在同尺寸下选择不同模式：本步 Firefox 在 1440×900 的一次返回中空间不足，扩大可用高度后才开放沉浸切换。这是有效降级，不应通过降低安全边界强行展示。

## 第十四步应做的整体验收

按真实访客路径走完封面、个人身份、经历、工具卡、AI 影像、Coding 完整网页、庭院与结束页。重点核对文字精简、操作可发现性、切换连续性、卡片实体质感、作品首屏与返回体验，以及公开分享前的入口和资源路径。

本步已有尺寸、输入、缩放、恢复和受影响功能回归记录；第十四步以最终构建验证完整路径和交付情况，不把早期中间构建记录当作最终结果。若再修改源码，只对变更和影响范围补充必要验证。

浏览器缩放、字号仿真、触摸仿真、WEBGL_lose_context、初始图形不可用模拟分别记录。自动化可用浏览器与实体手机、辅助软件的实测范围不能混写。

开发：npm run dev。构建：npm run build。开始下一步前建立新基线，不覆盖前十三步证据；仓库上传和发布按用户后续指示处理。
