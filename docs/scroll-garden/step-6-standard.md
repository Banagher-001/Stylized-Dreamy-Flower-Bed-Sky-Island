## 5. 6.4：B1上部——主影像从柱旁展开

呈现顺序：**02符印点亮 → 少量边框线浮现 → 海报展开 → 标题与一句介绍完整出现。** 画面从符印附近建立空间联系，最终成为稳定的影像窗。装饰停留在边角与连接处，海报本身清晰。

真实模式为「代表动画」：一张主海报、真实片名、一句介绍、已提供的形式/时长和「播放影片」入口。真实时长从媒体元数据获得，缺少的年份/职责等字段不显示。

当前示意模式采用「影像展映」：用现有概念封面演示构图，常驻样片标识，只提供真实可用的「查看画面」入口，不画一个无法播放的三角按钮。

桌面以一张主画面为焦点，初始画框宽度约520～560px，根据柱面、导航和可用高度计算；横幅保留原比例，标题与说明独立排版。竖幅海报采用窄幅主图与旁侧说明，避免把人物/主体裁成横幅。完整画面可从查看入口打开。

**通过条件：**B1完整阅读时有明确主视觉，片名/样片状态清楚；图像保持比例和主体，入口只对应实际能力。完整阅读区不自动换画面或漂动。

## 6. 6.5：B2中上部——画面切片与本人职责

真实模式为「分镜与我的职责」：一张较大的关键画面与最多两张小画面错位排布，共同属于B1项目；旁边附简短说明及已提供的本人负责内容。只有确为制作分镜的素材才标「分镜」，从正片采样的图片标「影片画面」。

职责区只有事实：例如用户实际提供后才写具体负责项，不从「在枫叶互动制作AI动画」推断某部作品由本人独立导演、编剧或完成全流程。

当前示意模式为「画面切片」：同一概念主视觉的完整图与局部视图，标明「全景／局部／细节」和设计样片属性；不写成真实制作过程，也不把无关概念图拼成同一项目的分镜。

画面按滚动共同展开，完整阅读阶段全部保持；不增加自动轮播或需要横向滑动才能看完的胶片条。点击可查看对应完整图，关闭回到当前站。

**通过条件：**能看出画面属于哪个项目/示意源；完整图与局部有区别，职责可追溯；手机布局不把三张大图纵向堆到屏外。

**通过条件：**两种比例都有合适展示，原图可看完整，当前图名和状态准确；满阅读区图像、亮度与布局稳定，不挤占符印/导航。

**通过条件：**有目录的每项入口可用；无目录时画面完整且没有空白大卡片或失效操作；8.0H后第二柱阅读内容隐藏，离柱转场连续。

## 9. 6.8：放映与全尺寸查看的行为合同

影像窗中的动作和环境播放分开：滚动负责章节/镜头，点击「播放影片」才进入放映。`查看画面`只打开原图，不伪装成播放。

| 情况 | 约定行为 |
| --- | --- |
| 打开 | 保存站点、段内比例、当前画面模式与环境的手动播放选择；暂停背景相机/环境更新，焦点进入对话框 |
| 放映 | 原生可访问视频控制、`playsinline`，不自动循环；首个用户点击可请求播放，浏览器拒绝时提供明确播放入口 |
| 声音 | 无自动有声预览；影片声音由用户明确播放与原生控制管理，原本无声的素材不虚构音轨 |
| 弹层内输入 | 视频控制、键盘和内部必要滚动正常工作；wheel/触摸不推进背景庭院 |
| 关闭 | 关闭按钮/ESC可用；停止当前媒体，恢复庭院原站及段内比例，焦点回到原触发按钮 |
| 关闭后媒体 | 停止声音和播放，解除已关闭媒体的来源/加载；再次打开从开头开始 |
| 切换作品 | 先停止并释放前一个，只允许一个活跃video |
| 标签隐藏 | 暂停影片及场景；返回后影片保持暂停，由用户再次播放 |
| 弹层内改尺寸 | 关闭时按保存的叙事位置和新可视高度恢复，不能直接套用旧scrollY |
| 加载失败 | 显示可读状态、可用的重试/关闭入口，庭院位置可恢复，不留无限加载层 |
| 仅外部页面链接 | 标为「打开影片」并指向真实地址；不把平台网页URL当作可内联播放的视频文件 |

采用清晰的全尺寸媒体层。图片按`contain`完整显示，有可访问标题/说明；影片以原比例居中。关闭控件至少44×44px，焦点不会进入背景。长说明允许在对话框内阅读，柱旁主要内容本身无内部滚动。

**通过条件：**关闭/ESC、快速开关、切换、加载失败、标签切换、改尺寸和上下文恢复均不丢失庭院进度；关闭后无继续播放/声音，背景没有积压滚动。真实影片缺失时，用隔离夹具验证机制并明确记录接入缺口。

## 10. 6.9：显隐、画幅与性能边界

### 滚动显示

每段内0～15%唤醒符印，15～30%依次建立边框、媒体及标题说明，30～80%全部稳定，80～100%退出并进入下一次下降。所有显隐取自同一滚动状态，不能再加一条强制播放的秒数时间轴。

快滚直接到当前站；倒滚恢复同一叙事状态；停在中途保持中途。减少动态时采用稳定画面/直接定位，关闭光尘与展开位移；用户主动播放影片仍可用。第一柱的显隐区间与文字保持。

### 当前尺寸验收

- 目标为1440×900、1366×768、模拟390×844。影像使用独立尺寸模型，以原比例、实际可用区域和UI矩形冲突计算布局。
- 桌面柱在左、影像在旁；影像窗初始宽约520～560px，实际高度须避开页头、导航与页脚。左侧章节提示与右侧媒体可处于相同高度，但实际矩形不相交。
- 手机在符印下安排紧凑影像窗。横图可采用上图下说明；竖图采用小海报与旁侧说明；B2用一主两小的紧凑组合。核心标题/说明/状态和可用入口同时完整，详细说明放进查看层。
- 手机左右至少16px，与顶部/底部控制保持至少16px安全间距；符印实际可见范围不被遮住。布局容不下时先减少非必要说明与装饰、调整媒体尺寸，保持所有核心信息与正常阅读字号。
- 正文/实质说明桌面18px、手机至少16px，标题约27/22px，实际文字与底色对比度≥4.5:1；样片标识须可读且始终与图片对应。
- 图片有稳定比例框与加载状态，解码完成不能把文字、镜头或导航顶走；不拉伸、不裁掉作品关键信息。默认完整展示，局部切片明确标注且可查看原图。

### 资源与加载

作品图片/视频采用清晰DOM媒体层，复用现有Three.js场景与共享环境时钟；不加第二个三维画布、全屏Bloom、逐帧海报噪声或默认循环视频。

媒体在接近第二章时按需设置来源/加载，优先当前及下一站。离章后释放不再需要的影片，隐藏画面不持续解码播放。仅设置`loading=lazy`不能代替实际请求时序检查。图片尺寸按显示需要选择，原图在用户查看时加载；现有两图可先复用，不重复生成多个大文件。

第二柱材质/符印优先共享现有资源。实施前记录同模式/同预热路径的基线，GPU增量预算为几何≤2、纹理≤1、活动模式程序≤1、两模式缓存程序≤2；需要调整时先减装饰并在验收中记录原因。以第五步54/4/10及两模式18为参考，不把它当作第六步新测基线。

光尘同时活跃上限仍为桌面24、手机12，稳定阅读8/4，减少动态0。独立池须预分配且有总量记录，最多按两柱配置桌面48/手机24个槽位，不按四站各建一池；非当前柱不绘制/更新光尘。DOM媒体解码成本单独观察，renderer.info不代表全部浏览器媒体内存。

同脚本性能在本次执行前后各保留30个原生wheel停止样本，测量期间不截图/不并行跑其他浏览器检查，以新测基线比较。p95增加超过约10%先排查解码、重排和重复绘制，保留全部样本与峰值。第五步212.3ms的受控p95与348.1ms诊断峰值是历史记录，不是本步实测或帧率保证。
