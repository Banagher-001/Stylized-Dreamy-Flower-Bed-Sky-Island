## 3. 12.2：把庭院整理为正式默认首页

本方案建议采用下表；用户之后明确开始本步时实施，用户另有入口指示则优先遵循，不在执行中再次重复确认同一选择。

| 地址形态 | 本步计划行为 |
| --- | --- |
| 默认地址，无tour参数 | 直接打开三柱滚动庭院，由容量/系统偏好选择沉浸或稳定阅读 |
| `?tour=prototype` | 继续作为庭院兼容入口，旧收藏/演示链接仍能用 |
| `?tour=reference` | 明确打开此前参考作品集，供审阅与退路使用 |
| `debug=1` | 显式工程检查，不进入普通访客界面 |

**通过条件：**访客不用知道原型参数就能进入庭院；新默认、兼容入口、参考入口分别可用；错误退路不自循环，媒体返回与章节导航仍在当前页面正确工作。

## 7. 12.6：核对性能、资源与真实设备边界

保留DPR上限2、默认像素设计分辨率384及唯一绘制系统。本步入口/交付工作新增GPU资源预算为0；十次模式与媒体循环后无持续几何/纹理/程序、DOM或解码实例增长。暂停停稳、真实隐藏和不可见封面不持续绘制；相同尺寸不反复分配缓冲。

若最终修复触及渲染、滚动、布局热路径或需要新性能结论，在同一环境独立重测前后各30次原生wheel：五路线各六次、相同画幅/模式/预热/时间，测试时不并行录屏、截图或另一浏览器。p95恶化超过10%须查因处理，不挑最好样本。只继承既有性能证据时明确写历史结果与适用源文件，不将182.8ms称作本次新测。

核对静态资源请求、缺失文件、控制台异常和媒体加载时机。保持按需加载与明确用户播放；稳定阅读展开的静态图与实际播放的视频分开记录。打包/压缩不擅自降低主体画质、缩正文或改动水体来凑指标。

真机条件可获得时，补测iOS Safari/Android Chrome的真实滑动、惯性、浏览器栏/安全区、旋转、大字、双指缩放及查看器返回；实际VoiceOver/TalkBack、物理触控板/APZ与硬件FPS另列。没有设备时完成其他工作，提供可操作的真机复核表，保持“待复核”，不宣称全平台通过。

**通过条件：**性能结论有真实来源与版本；当前环境资源/生命周期检查通过；物理设备能力不由模拟推断，未测项与技术交付完成分开。
