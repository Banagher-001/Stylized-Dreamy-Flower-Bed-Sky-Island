## 10. 7.9：共同的输入、布局、恢复和成本合同

### 进度与项目层

| 情况 | 合同 |
| --- | --- |
| 主叙事滚动 | 当前站点与显隐来自实际文档进度，慢滚/快跳/倒滚一致；0～15%唤醒，15～30%显现，30～80%稳定，80～100%退出 |
| 打开项目层 | 保存站点及段内比例，锁定叙事进度；焦点进入项目层，背景控件不可访问，不新增历史记录 |
| 现场体验 | 单一画布显示全景；环境按当前明确选择运行，读柱进度冻结 |
| 项目档案 | 背景时钟/绘制暂停，原生媒体按明确点击播放；档案内滚动不影响庭院 |
| 关闭/ESC | 停止并清理档案媒体，按新视口恢复原站及比例，回焦原入口，保留用户最新主动设置 |
| 改尺寸 | 主阅读保持站点/比例；项目层内改变尺寸后再关闭，也按比例计算，不使用旧scrollY |
| 标签隐藏 | 场景停止时间推进/绘制，视频暂停；返回时视频保持暂停，实时场景按最新用户选择恢复 |
| 上下文中断 | 保留进度和项目页签状态，可关闭/返回；恢复后不跳到开场或启动第二场景 |
| 快速切换/重开 | 单一项目/媒体所有者，迟到的关闭或载入回调不能清理新打开的视图 |
| 减少动态 | 直接定位、抑制展开位移与光尘，默认静止；明确的播放/模式操作仍可用 |

现有第六步的图片/视频查看合同继续保持；项目层生命周期应增量整合，避免两个独立暂停/恢复逻辑互相覆盖。关闭后恢复位置与环境时钟分别判断，不要求播放过的水波倒回旧画面。

### 当前尺寸

目标为1440×900、1366×768、模拟390×844，三站核心信息完整可读。正文桌面18px、手机至少16px，标题约27/22px，实际背景对比度≥4.5:1；手机左右至少16px，阅读层与控制区至少16px间隔，符印保持可见。

C1采用短文与轻量图，C2采用紧凑项目封面/说明及双入口，C3用短结语。主要阅读区域无内部滚动，档案允许在专属区域滚动。先去除重复说明/装饰、调整媒体组合，不通过缩字号、截断核心信息或隐藏按钮使目标竖屏“通过”。

现场体验的控件和主要场景物体要同时可用；档案图像保留比例、按钮可键盘/触摸操作、焦点可见。新封面按接近C章加载，视频仅在打开档案并明确播放时请求；载入状态有稳定尺寸和清楚的失败提示。

第六步已有的手机阅读层至多1/255通道差异、云软件延迟峰值等限制继续保留；狭矮横屏、完整手机静态章节和200%文字缩放仍待第11步，不能替代本步目标竖屏的修正。

### 资源与性能

不创建第二个Three.js场景、渲染器或体验iframe，不以预录片段假装现场体验。新增GPU资源的预算为几何≤2、纹理≤1、活动模式程序≤1、两模式缓存程序≤2；03优先复用现有着色代码。第六步充分预热的56/5/10与两模式18仅为历史参考，本步要新测基线。

执行前后用同一C区域路线、视口、固定环境时间与预热方式，各保留30次实际wheel停止原始样本，不截图/不并行跑其他浏览器检查。p95增加超过约10%先排查布局、解码、重复绘制，保留全部样本与峰值；不保证物理输入到显示延迟或云端硬件FPS。

另做至少10轮「读柱→现场体验→档案→关闭」，核对DOM、GPU、canvas与video当前数量不增长。手动暂停后的体验、档案和主阅读应按各自合同停止非必要绘制；主动播放场景时正常绘制不能记为泄漏。
