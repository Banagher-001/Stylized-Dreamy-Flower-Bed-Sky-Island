# 第一步执行标准：运行核查与接入资产整理

## 范围

检查源为 `luosen-asset/lawson-blender/out/web_final/`；接收方是本仓库默认入口的三柱个人网站。执行独立预览、原始功能检查、最小资源整理、临时嵌入诊断和事实记录。正式展位与正式嵌入由后续步骤实现。

## 必须完成

1. 记录两个仓库的提交、远端 main 和执行前状态，保存运行输入的 SHA256；原有本地工作要得到保留。
2. 从 HTML、import map、ES Module、CSS 和模型引用追踪运行依赖，列明文件、大小、SHA256、模型内嵌/外链资源与 Three.js 版本。制作资料与访客运行文件分别列明。
3. 通过 HTTP 实际运行，验证首次/再次加载、场景对象、昼夜、八组灯光、三辆车、两名店员、视角、漫游、自动门和代表性实际点击。每个结论有日志或画面支持。
4. 在隔离的临时副本中验证站点子目录和同源 iframe：实际模型就绪、尺寸变化、滚轮/键盘隔离、全屏、鼠标锁定、卸载及模型加载失败后的返回。
5. 分别核查准备完成、暂停动画、持续绘制、后台计时、退出漫游和销毁的边界。记录现有接口与后续要实现的接口；iframe 的 load 事件不能代替场景 ready。
6. 记录环境与性能基线；手机视口与触摸模拟用于说明现状，真实设备与硬件 GPU 测试须分别表述。弱设备、减少动态与图形不可用时的问题进入明确后续步骤。
7. 交付版本/资源清单、功能核查记录、接入可行性说明及问题清单。复核两个仓库的运行输入哈希和源仓库状态。

## 完成判据

- 独立场景可加载，关键资源完整，主要功能逐项核查。
- 运行包可离线依赖本地文件，子目录嵌入有实际浏览器依据。
- 正式接入所需的控制与生命周期缺口、移动端和环境局限均有记录与归属。
- 无法打开、关键资源缺失或核心交互不可用属于本步阻塞，解决并复核后才能通过。
- 第一阶段的通过表示“基线与接入条件已核实”，不表示后续步骤已实现，也不表示物理手机或硬件性能已验证。

## 证据原则

只在 `docs/evidence/lawson-integration-step-1/` 写入本轮证据。旧报告和历史 ZIP 保持封存状态。原始失败与中断记录保留，复核必须注明失败原因、修正范围和对应新记录。浏览器诊断包装只存在于测试上下文，不改变场景源代码、时间流速或生产配置。
