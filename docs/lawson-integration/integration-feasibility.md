# 接入可行性与接口边界

## 接入位置

当前默认网页是三柱滚动作品集，第三根石柱「03 / 交互实验」的 C2 是作品展示位置。它目前只绑定庭院习作。推荐在同一展位切换罗森与庭院，默认显示罗森；完整体验在作品查看层打开。C1 创作介绍、C3 结尾和三柱运镜关系继续作为设计基线。

依据：`src/tour/experimentReading.ts`、`createExperimentReader.ts`、`createProjectViewer.ts`。面板有屏幕容纳检测，第二步应在约 500px 的桌面展示宽度和稳定阅读模式下分别设计，控制双作品索引增加的高度。

## 资源与运行边界

- 源运行目录为 `luosen-asset/lawson-blender/out/web_final/`；必需文件 46 个，20,332,784 字节，四个模型占 18,648,040 字节。
- 罗森 Three.js r160，庭院 three 0.187.0。罗森的本地 import map 和页面级 CSS 应保留在独立文档中，由同站 iframe 隔离。
- 后续拟定路径为 `experiments/lawson/index.html`；按资源清单随个人网站部署。私有 GitHub 是开发来源，不是访客的运行时资源服务器。
- 所有相对依赖均保留目录结构。根目录、子目录和 iframe 的实际结果见本步浏览器记录；临时试验位于 `/tmp/lawson-step1-audit/`，未向个人网页的 public/src 添加罗森资源。

## 现有源接口的真实含义

| 事项 | 现有能力 | 后续接入要做的事情 |
|---|---|---|
| 模型可操作 | `window.__LAWSON__.ready` 在首帧后设为 true | 场景就绪握手；与 iframe load 分开 |
| 错误 | `__LAWSON__.error`、原场景 fatal 面板、加载超时 | 父层保留返回与重试，将明确错误传给父层 |
| 暂停动画 | `api.pauseAll(v)` 设置动画及 loop.paused | 把“暂停动画”和“完全停止绘制”分开控制 |
| 持续绘制 | UpdateLoop 每帧继续请求 RAF，main 每帧 render | 背景庭院暂停；不可见的罗森停止持续绘制 |
| 停止循环 | UpdateLoop 类有 stop，但未通过公开 API 暴露 | 第五步建立显式运行生命周期 |
| 切到后台 | visibilitychange 只重置 last 时间；浏览器还可能自行节流 | 建立明确的可见性策略，恢复时重置时间 |
| 退出漫游 | CameraSystem.exitWalk 可退出鼠标锁定，源页面有 Esc 处理 | 父子层协商 Esc；漫游优先退出，再处理作品层关闭 |
| 全屏 | 原按钮对“子页面 documentElement”请求全屏 | 正式作品容器接管全屏，或在子页面保留返回作品入口，确保返回按钮属于当前全屏内容 |
| 关闭 | 源页面没有完整对外 dispose 接口 | 清理监听器、计时器、运行循环、指针锁定及运行资源，或卸载整个 iframe |
| 嵌入通信 | 没有现成 postMessage 桥 | 第四/五步新增小型、可校验来源的通信契约 |

`pauseAll` 不冻结原始 rawDt、cameraSystem 或昼夜过渡；也不代表 WebGL 上下文已释放。浏览器记录会单独记录其暂停后的绘制次数，不能用按钮文字来判断后台成本。

`getState()` 是 UI 缓存，不是全部实时变换的快照。例如主循环只刷新 traffic 的部分字段，车辆位置与车轮应使用 `getVehicleState(tag)` 核查；公开 `project()` 返回取整的 CSS 像素，不能用于要求无限精度的视角比较。第一步的定向复核按这些实际接口边界记录证据。

## 个人网页需要扩展的地方

1. **作品数据**：从固定 courtyardProject 扩展为有项目 ID、封面、摘要、体验类型和档案内容的数据结构。
2. **C2 展位**：目前回调只有 `open(tab, trigger)`，需要携带项目身份，并记住选中的作品。
3. **作品层**：庭院继续使用现有主画布；罗森使用按需建立的独立 iframe。切换档案与体验时，各自采用适合的暂停/卸载方式。
4. **主站渲染门控**：`startTourPrototype.ts` 当前 covered 只判断 media 或 archive，live 专用于庭院复用画布。外部场景的 live 必须单独识别，并暂停庭院绘制。
5. **返回阅读**：沿用现有 capture/restore、mediaProgress 和触发按钮焦点恢复；打开时停止自动导览，关闭后由访客主动恢复导览。
6. **降级入口**：当前 live 入口全局依赖主庭院可用性。后续按作品身份管理体验可用状态，始终保留项目档案和返回入口。

## 后续拟定的最小通信契约

这是后续实现建议，不是第一步已经接入的能力：

- 子页面向父层报告 ready、error，以及漫游/全屏/暂停状态。
- 父层向子页面发送运行、暂停、退出漫游和关闭请求。
- 每条消息带项目 ID 和协议版本；父层核对消息来源窗口与 origin，忽略已关闭实例的过期消息。
- 父层关闭入口独立于子场景；模型出错时仍能返回。关闭时清理该实例，并恢复原来的 C2 阅读状态。
- 正式全屏应包含作品的返回控件；鼠标锁定时先允许 Esc 释放锁定，再执行作品层关闭。第一步验证原场景的权限能力，最终交互由第五步统一。
- iframe 的卸载停止回调可在临时试验中验证；显卡内存实际回收时间不能由这个现象单独证明。

## 留给第二步的设计输入

重点素材是蓝色招牌、方块樱花、温暖店内灯光和室内陈列。柱旁使用简洁封面和短介绍；完整昼夜、店员、车辆与漫游进入宽敞的作品体验层。手机默认控制台遮挡与触摸操作的现状由本步记录，第二步确定入口层级，第六步完成正式适配。
