## 3. C2 展位：先看作品，再进入完整网页

### 3.1 位置和作品身份

- 沿用第三根石柱 C2。C1 创作介绍、C3 结束段与原运镜位置继续使用。
- C2 提供两项作品选择：`LAWSON / 罗森便利店`、`COURTYARD / 庭院习作`。
- 首次进入本页面默认选择罗森。关闭体验层后保留本次选择；刷新从默认重新开始。本步不设计跨设备或跨浏览器记忆。
- 切换作品更新当前标题、封面、类型、摘要和两项入口。两套详情不同时堆在柱旁。
- 切换属于访客接管，停止自动导览并停留在当前位置，避免刚切封面就自动离开。

### 3.2 罗森预览内容

| 元素 | 定稿方向 |
|---|---|
| 标题 | 罗森便利店 |
| 类型 | 交互网页场景 |
| 摘要 | 在一家微缩便利店里，切换昼夜，观察店员与车辆。 |
| 主入口 | 进入完整网页 |
| 次入口 | 项目档案 |
| 封面 | 原场景真实画面，以店面、招牌及场景氛围为主体；不使用庭院图冒充罗森 |

封面只加载轻量静态图片，不运行隐藏 iframe，不预加载四个模型。庭院继续使用现有封面及资料。预览不得将第一步已确认的问题写成无条件可用的功能承诺。

### 3.3 视觉及空间

- 保持现有深绿、浅金和魔法文字风格；罗森蓝用于小面积作品标识或选中指示。
- 桌面延续柱旁约 500px 内的面板约束。封面维持宽画面，常规高度控制在约 140–180px；最终按样稿实测，避免入口挤出可读区。
- 每次只显示当前作品的内容和按钮。字体不通过缩小来迁就堆叠。
- 容纳不足时使用已有稳定阅读模式，保留所有文字和入口。
- 作品选择项及主要按钮至少 44×44 CSS px；有可见选中态和键盘焦点态。
- 作品切换使用短暂淡入，减少动态设置下直接更新。作品选择的键盘语义、标题关联及读屏状态必须随样稿说明。

## 4. 大尺寸体验层：把空间留给完整原页

### 4.1 结构

罗森模式只保留一条紧凑宿主工具栏，其余空间给完整原网页：

1. 工具栏左侧：作品名称。
2. 工具栏中部：现场体验 / 项目档案。
3. 工具栏右侧：独立打开 / 返回阅读。
4. 工具栏下方：原网页占满余下可用宽高。

正常体验时没有常驻侧栏、底部说明栏或大面积外边距。长介绍和过程图放在档案内。罗森界面不套用庭院的正常/像素切换及环境播放按钮；原页已有的全部控件原样保留。

沿用唯一作品 dialog，作品身份在打开时确定。体验层内切换现场/档案；要换另一个作品，返回 C2 选择。不会并列开启两个作品层。

### 4.2 尺寸标准

以下按常规字体、无安全区估算。实际采用可视视口及工具栏测量值，不硬编码画布分辨率。

宽度不大于 767px，或高度不大于 480px 时采用紧凑工具栏。紧凑栏将作品名缩为“罗森”，页签显示“体验 / 档案”，独立打开使用带完整可访问名称的 44px 图标按钮，返回按钮显示“返回”；完整操作名称仍通过可访问标签提供。320px 宽或字体放大时可换行，不能为了维持 48px 而裁切按钮。

| 视口 | 工具栏目标高度 | 原网页目标可用区域 |
|---|---:|---:|
| 1920×1080 | 56px | 1920×1024 |
| 1440×900 | 56px | 1440×844 |
| 1366×768 | 56px | 1366×712 |
| 768×1024 | 56px | 768×968 |
| 390×844 | 48px | 390×796 |
| 844×390 | 48px | 844×342 |

- 宿主层宽度为可用视口的 100%，无桌面最大宽度限制；高度随可视视口变化，使用动态视口单位并提供回退。
- 布局采用工具栏自动高度 + 剩余空间；iframe 区域 `min-width: 0`、`min-height: 0`。
- 原网页不固定为 16:9，不用 CSS scale 缩小，不加滤镜、透视或透过网页的装饰叠层。
- 手机为工具栏和内容处理安全区；仅扣除真实系统安全区，不额外添加展示性留白。
- 320px、小横屏及文字放大时允许工具栏自然换行，优先保证返回和主要操作完整；届时原页高度按工具栏实际高度计算。
- 原页自身响应式限制沿用第一步记录。外层变大不能被当成已解决原页手机布局的证明。

### 4.3 外观

工具栏使用深绿底、浅色文字和克制的细线，进入内容区后保留原网页自己的蓝色与界面风格。打开时只对宿主外框做约 120–180ms 的淡入，不对原网页正文做变形。减少动态设置下取消过渡。

## 5. 固定交互规则

| 操作 | 预期行为 |
|---|---|
| 在 C2 切换作品 | 更新轻量预览，保留阅读位置，停止导览 |
| 进入完整网页 | 捕获阅读状态，打开工具栏，停止庭院绘制，后续第五步按需创建原页 |
| 原网页内操作 | 滚轮、触摸及键盘按原页面规则处理；不带动主站运镜 |
| 切项目档案 | 移除罗森 iframe，显示该作品档案，庭院保持停绘 |
| 从档案重新进现场 | 创建新实例，从原页默认状态开始 |
| 独立打开 | 打开同一部署下的同一原页入口；它是新的页面实例 |
| 返回阅读 | 清理体验实例，恢复原作品选择、C2 阅读位置和焦点 |
| 返回后的自动导览 | 维持停止，由访客主动继续 |
| 返回后的环境动效 | 恢复打开前的设置，不强制改为播放 |

主站记住的是作品选择及阅读位置；不承诺保存已经卸载的子页面现场进度。以上规则在设计交付中明确说明，避免后续实现临时更改。

### 5.1 全屏与 Esc

- 普通作品层已占满浏览器可用区域，顶部“返回阅读”保持可用。
- 原网页自己的全屏按钮继续使用其原逻辑。进入原生子页全屏时，宿主工具栏可能按浏览器规则被隐藏。
- Esc 和系统退出手势先用于原网页退出漫游或全屏；退出原生全屏后，宿主工具栏重新出现。
- 焦点在 iframe 内时，宿主不把 Esc 直接解释为关闭整个作品，不覆盖原页键盘行为。焦点在宿主外层时，Esc 可关闭作品层。
- 原生 dialog 的 cancel 行为必须在第四/第五步按上述规则处理，不能只添加一个全局 Esc 关闭监听器。
- 不在子页注入新返回条或替换原全屏按钮。跨设备实际支持在第六步验证，不能凭桌面结果保证所有设备一致。

### 5.2 焦点、滚动与返回

- 打开后先聚焦宿主返回按钮，保证有明确退出入口；点击原场景后由原页接收输入。
- 外层锁定背景滚动并使背景不可交互；保留 iframe 内控件的滚动和触摸操作，不全局取消所有 wheel/touch 默认行为。
- 使用原生 modal 的焦点管理，额外核对 Tab/Shift+Tab 穿过 iframe 的情况，避免自写拦截破坏子页输入。
- 关闭后将焦点还给实际触发按钮，采用 preventScroll；按钮消失时回退到当前作品选择项或 C2 标题。
- 使用现有 readingLayout.capture/restore。保存阅读模式、锚点、段内位置及运镜进度；视口变化后按锚点恢复，不机械写回旧 scrollY。

## 6. 状态设计：宿主状态不冒充原页功能

| 状态 | 宿主显示 | 原网页处理 |
|---|---|---|
| closed | C2 展位 | 无 iframe |
| opening | 打开工具栏和页面区域 | 捕获状态、锁定背景、停止庭院 |
| loading | 克制的载入提示 | 保留原页加载界面；不能把 iframe load 当作场景就绪 |
| ready | 完整原网页 | 原 ready 为 true，且原 fatal 未显示 |
| slow | 载入较慢，可等待或重试 | 继续观察原页，不制造百分比或伪装失败 |
| error | 原错误界面及宿主可恢复操作 | 不遮住原重试按钮；返回和独立打开仍可用 |
| archive | 对应作品档案 | 罗森 iframe 已卸载 |
| closing | 返回原阅读位置 | 先使旧回调失效，再移除实例并恢复主站 |

- 约 12 秒未就绪可显示 slow；只有明确原错误或文档失败才标 error。原页自身约 30 秒启动守卫仍按原版运行。
- 原错误需综合现有 `__LAWSON__.error`、`body.dataset.ready` 及原 fatal 显示状态，不假定每个启动错误都会写入同一字段。
- 原页 fatal 已显示时，宿主不能遮住它，也不能仅因 ready 曾为 true 就显示成功。
- 宿主重试更换页面实例并清理旧监听/计时器；原页自己的重试继续按原逻辑刷新。
- 状态只读原页面已有信息，不加入通信桥、不更改原 ready/error 标记、不通过强制调用 API 制造通过。
- 样稿可演示这些状态，但要标为设计样稿；它不构成真实原页已成功加载的证据。

## 7. 生命周期与主站绘制契约

| 当前内容 | 庭院绘制 | 罗森 iframe | 自动导览 |
|---|---|---|---|
| C2 正常阅读 | 按主站既有设置 | 0 个 | 按访客选择 |
| 罗森 loading/ready/slow/error | 停止 | 最多 1 个 | 停止 |
| 罗森档案 | 停止 | 0 个 | 停止 |
| 庭院现场体验 | 按现有庭院体验逻辑 | 0 个 | 停止 |
| 任一作品关闭 | 恢复原设置及位置 | 0 个 | 等待手动继续 |

- 必须同时区分 projectId 和 tab，不能再把全部 live 当成庭院现场。
- 主站停绘使用现有渲染门控，不能只隐藏 DOM 或把动画时间设为 0。
- 罗森离开现场后通过卸载停止回调；不拿原 pauseAll 充当渲染停止或 GPU 内存已回收的证明。
- 子页面在浏览器后台的行为保持原版；第一步没有可靠实测真实隐藏事件，不在设计中将其写成已解决。
- 关闭期间重复点击、快速开关或旧加载完成都不能重开旧实例，后续用实例代次和来源窗口识别过期回调。

## 8. 给后续实现的接口与路径定稿

### 8.1 作品数据

```ts
type ProjectId = 'lawson' | 'courtyard';
type ProjectTab = 'live' | 'archive';
type ProjectExperience =
  | { kind: 'host-scene' }
  | { kind: 'embedded-page'; entryPath: 'experiments/lawson/index.html' };
```

作品查看层调用定为 `open(projectId, tab, trigger?)`。档案和现场都必须根据项目身份取数据，不再直接导入固定的庭院常量。

| 项目 | 约定 |
|---|---|
| 原文件来源 | `luosen-asset/lawson-blender/out/web_final/` |
| 第三步迁入位置 | `public/experiments/lawson/` |

### 8.3 计划涉及的宿主代码位置

- 作品注册表：拟新增 `src/tour/projectContent.ts`，复用现有庭院资料，增加罗森身份和体验类型。

- 统一查看层：扩展 `createProjectViewer.ts`，罗森使用紧凑布局修饰，不干扰庭院原体验布局。
- 罗森实例管理：第五步拟新增 `createLawsonExperience.ts`，职责限于创建、读取已有就绪/错误、重试和卸载。
- 主站协调：`startTourPrototype.ts` 按作品身份调整绘制门控、返回及导览。
- 稳定阅读和降级：`createReadingLayout.ts` / `readerFlow.ts` 按作品分别处理入口可用性；庭院失败不直接禁用罗森尝试入口，档案和返回始终可用。
- 样式：宿主选择器限定在作品层及 C2 内，不向原网页写入 CSS。

上述接口先作为设计契约，正式代码分第四/第五步实现。iframe 保留独立文档、本地 import map 与 CSS；原生全屏权限明确允许，原鼠标锁定依用户手势获取。采用受控同源原页，不附加会限制原功能的 sandbox，也不添加不存在的 pointer-lock 权限策略指令。

## 10. 第二步验收标准

1. C2 可明确分辨罗森与庭院，默认罗森，且切作品不会出现两份详情叠高。
