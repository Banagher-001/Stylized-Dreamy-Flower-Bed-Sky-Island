# 原页问题与测试边界

本表描述固定原版本自身的行为。第一步只核查和记录，未修复原页面。后续“完整嵌入”以保留该版本为基准，不能把已知问题包装成正常功能，也不能把原有问题算成嵌入新增的问题。

## O1：N 调试快捷键与 README 不一致

原 README 提到 N 打开店员调试 HUD；实际运行文件没有 `KeyN` 绑定。真实按 N 后可见 HUD 状态不变。现有调试 API 仍在结构清单中，但不能把 N 宣传成可用快捷键。

证据：`run-1/controls.json` → `DOC.KeyN`。不影响原页面通过现有按钮使用。

## O2：拖动后复位仍有镜头惯性偏移

复现：全景 → 鼠标拖动旋转 → R。原镜头切回 hero，原补间动画确实结束；后续投影仍偏离初始画面并继续漂移。原 `CameraSystem` 在预设飞行中调用带阻尼的 `OrbitControls.update()`，没有清除之前的旋转残量。

证据：`run-6b/controls.json` → `KEY.KeyR`，记录实际按键、初始画面、拖动、动画结束和后续两次样本。早期 `run-1`、`run-5` 的等待超时保留。旧核查的某次重置误差较小，不能据此宣称所有拖动时机都可精确复位。本轮未改变公差来伪造精确恢复。

## O3：漫游中 R 退出后，界面缓存可能仍显示漫游

复现：点击室内漫游 → R → 点击夜晚。实际相机已退出漫游且鼠标锁定已释放，但原 `KeyR` 分支没有同步 `UIState.walk`；后一次界面同步可重新显示漫游提示和激活态。

证据：`run-7/keyboard.json` → `BOUNDARY.R-in-walk`，并附截图。原“重置视角”按钮能同步退出状态，可作为原页现有恢复方式。本步未改快捷键处理函数。

## O4：漫游初始区域的前后移动被碰撞挡住

原漫游起点约为 `[0.4, 1.62, 5.6]`。真实 W/S 输入均进入原 `_walkUpdate`，但被测起点处平面坐标不变；用真实 A 横移到约 `x=1.36` 后，W 仍被挡住。只看到上下轻微摆动不能算平面行走成功。

证据：`run-7b/keyboard.json` → `KEY.KeyW` / `KEY.KeyS`，包含原按键、原 dt、处理前后位置、原碰撞盒及真实定位过程。源实现将同类物件合并成较大的 AABB；多个碰撞盒覆盖起始位置。该结论限定于被测起点和横移位置，不声称每个位置都不能前后移动。

A/D 平移，以及左右 Shift+A 的加速均有实际位移。旧的 S 测试只比较投影变化，可能把进入漫游和上下摆动算作变化；当前绝对平面位移结论取代旧记录对此项的概括性“通过”。

## O5：原手机界面可加载，但布局与漫游有局限

390px 宽时原展开面板为 200px，约占一半画面；品牌与顶部按钮重叠，多个可见控件的点击区域至少一边小于 44 CSS 像素。原页面没有触摸漫游方向按钮。旧触摸模拟已验证单指旋转、双指缩放和夜景点按；这不代表键盘漫游在手机上完整可用。

证据：旧 `compat-accepted.json`，新版 `run-9/readiness.json` 的原默认竖屏、横屏截图。此步保留原 UI；大尺寸外层能提供空间，不能宣称因此已解决原手机布局。真实 iOS/Android、实际全屏及鼠标锁定支持需要设备验证。

## O6：帮助文字中的“点击车辆”没有对应拾取入口

原帮助将车辆列入可点击物件，但原运行时的 17 类拾取入口没有车辆；`buildInteractives` 来自静态商店场景，车辆另行加入场景，未追加至拾取列表。原 `car` 处理分支的存在不等于已有可点击车体入口。

此项是帮助和绑定的静态、运行清单不一致；不冒充已完成车体每个像素的点击测试。三辆车均有原 UI 演示按钮，完整车辆流程另有实际观察记录。后续不能凭帮助文字增加新功能后称为原版保留。

绑定、拾取构造及其他问题涉及的原代码片段和文件 SHA256 见 [静态依据](../evidence/lawson-fullpage-step-1/static-findings.json)。

## O7：减少动态设置不会自动暂停原 JS 场景

旧测试已确认媒体条件匹配，但绘制仍持续。CSS 动效减少不等于 JS 动画暂停。此为原有行为，不在本步添加新开关。

证据：旧 `compat-accepted.json` → `reduced motion baseline documented`。

## O8：原 pauseAll 接口不是停止渲染

原调试 API `pauseAll(true)` 会暂停相关动画时间，但仍有绘制回调。正式外层生命周期不能把这个接口当作已释放或已停止绘制。

证据：旧 `core-accepted.json` → `pause semantics and lifecycle gaps measured`。关闭 iframe 后回调停止的旧可行性证据可复用，但不能据此承诺 GPU 内存何时归还。

## 环境、设备及测量边界

- Chromium + Mesa llvmpipe 软件渲染不是硬件 GPU；本步不承诺最终设备帧率。
- 原 FPS 采样基于被限制到 0.1 秒的 dt，HUD 不能直接当作墙钟实际帧率。旧独立性能采样约 2.1–2.4 次场景回调/秒，仅描述该云环境。
- 新版功能测试通过原按钮选择 low；默认截图在选择之前采集。原画质自适应降档属于原行为，不误认为测试改了默认配置。
- 手机版为 Chromium 的触摸和 DPR 模拟；窗口尺寸变化不等同物理手机旋转测试。
- 标签切换中，自动化新窗口、弹出标签及原生 Ctrl+T 均未可靠使原文档的 `document.hidden` 变为 true。本次只确认切换返回后仍就绪可操作；真实隐藏事件处理、后台帧率与能耗没有实测结论。原可见性处理代码已盘点，不伪造隐藏属性或事件。
- 车辆及店员为真实时钟观察，未穷尽随机任务和所有交通分支。完整文件清单保留这些代码，但不把观察覆盖写成穷举验证。

## 测试工具问题，单独归档

早期 CDP Esc 无法退出浏览器全屏；后经专用虚拟显示器上的 OS XTest Esc 实测通过。窗口识别先后遇到未映射辅助窗和缺少旧式窗口标题，均属于输入探针问题，未修改原全屏代码。

目标测试 `run-2` 在环境重启时中断；已完成的招牌点击保留，剩余 16 类由 `run-3` 补齐。早期移动测试以 W 作为加速路径，但该位置碰撞阻止移动，后改用已证实可通行的 A 验证左右 Shift，同时把前后移动限制单列。所有早期结果、脚本快照与中断说明保留。
