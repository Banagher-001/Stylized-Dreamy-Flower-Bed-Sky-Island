结论分为“原页与内嵌一致且功能通过”“原页已有问题”“宿主新增问题”“浏览器能力限制”“未验证”。原页问题、能力限制和未验证均不计作功能通过。正常日志与故障注入、原脚本既有拒绝分别归档，不吞掉异常制造干净日志。

**验收：**每项都有实际结果或明确的缺口；当前无法观察的效果不能从按钮变色、截图存在或 API 名称推断。

## 4. 鼠标、触摸、键盘和原生权限

桌面真实操作旋转、滚轮缩放、右键平移、相机切换和漫游鼠标观察。核对 13 条原键位记录：R、1、2、3、Space、Escape、W、A、S、D、左 Shift、右 Shift，以及原 README 提及但未绑定的 N。

R 的拖动后惯性问题、漫游中 R 的 UI 缓存问题、起点 W/S 碰撞和 N 未绑定按原情况对照。行走和加速观察真实平面位置，不能把上下摆动算成前后移动；可通行的 A 路径用于左右 Shift 加速对照。

原页获得焦点后，键位不驱动主站滚动、导览或阅读切换；主站工具栏获得焦点时按既有宿主规则操作。原漫游/全屏 Esc 和宿主关闭 Esc 分别验证：退出浏览器权限或漫游不意外丢失整个作品，宿主关闭仍可达。原生请求从原按钮和用户手势进入，退出用实际系统按键或原按钮，不能以 DOM Esc 冒充浏览器保留键。

触摸代表项为单指旋转、双指缩放、原控制台滚动和原按钮点按；不得将无触摸方向键的原漫游宣称为手机完整行走。沿用第六步对真实触摸协议与 DOM 模拟的区分。

**验收：**输入落在正确文档；主站背景不被原页操作带动；已支持的全屏/锁定可退出，拒绝或不支持时宿主仍可返回。与原版一致的异常单列，不改原代码掩盖。

## 7. 从个人网站入口完成整段使用流程

通过实际用户入口走完：个人网站进入 Coding/C2 → 选择 LAWSON → 大尺寸现场 → 原页操作 → 切档案 → 返回现场 → 关闭 → 继续个人网站阅读与运镜。另测刷新和从不同阅读位置进入/退出，记录来源焦点、阅读锚点和导览状态。

- 首次进入现场才创建原 iframe，等待原场景真实 ready，不能把 HTML load 当成模型完成。
- 原页面保持完整，使用工具栏后的可用大空间，不套固定卡片比例、截图或缩小整页。按子视口比较原布局，区分原版重叠与宿主新增裁切。
- 切档案和关闭卸载旧 iframe；重进按原默认状态开始，不承诺新增跨退出保存。
- 罗森现场/档案期间，主庭院按既有策略暂停绘制；结束后根据可见性、用户播放设置和阅读快照恢复，不自动续播导览。
- LAWSON 与 COURTYARD 的标题、现场、档案和独立链接各自对应；保留原庭院视频与两张图。水球入口仍进入 COURTYARD。
- 独立打开实际原入口，不依赖私有仓库登录，不自动弹新窗口；保持安全的新窗口关系。宿主焦点恢复、滚动锁及查看器所有权不串用。
- 检查根路径与 `/Stylized-Dreamy-Flower-Bed-Sky-Island/` 项目子路径：入口、原页相对资源、主站返回和独立打开均可工作。

**验收：**全过程可进入、可操作、可退出、可恢复，当前宿主最多一个罗森 iframe，退出后旧实例不再更新。任何打不开、退不出、丢失阅读位置或遗留活动实例均阻止本步通过。
