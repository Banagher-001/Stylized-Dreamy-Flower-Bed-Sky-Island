# 第四步执行标准：正式作品入口、大尺寸宿主与主站生命周期

状态：第四步已按下列标准完成。实际结果见 [第四步验收](step-4-verification.md)，后续接口见 [第五步交接](step-4-handoff.md)。

本步把第二步设计落实到真实个人网站：C2 双作品入口、统一作品查看层、罗森大尺寸宿主、真实独立打开、档案、主庭院停绘和阅读恢复。第五步再将第三步的完整原网页挂入稳定的宿主节点。

## 1. 输入与完成后的可见结果

依据 [第三步验收](step-3-verification.md)、[第三步交接](step-3-handoff.md)、[第二步设计](step-2-design.md) 和 [接口契约](step-2-interface.md)。

已就绪的原页入口为 `experiments/lawson/index.html`，public 和 dist 均已有 46 个原版文件，且已通过根目录及项目子目录独立运行核查。

第四步完成后，真实个人网站应呈现：

1. 第三根柱子 C2 默认罗森，可切换庭院，封面、文案和入口正确对应。
2. 罗森入口打开真实大尺寸作品宿主；顶栏、档案、返回与同源“独立打开”可操作。
3. 现阶段宿主显示诚实的准备态，例如“完整网页可独立打开，嵌入体验正在准备。”，提供真实独立入口、档案及返回。第五步用真实 iframe 替换准备内容。
4. 罗森准备态和项目档案打开时，庭院实际停止绘制；关闭后恢复原阅读与播放设置，导览等待用户主动继续。
5. 原庭院现场、正常/像素模式、动效开关、视频及早期帧图继续可用。

准备态不是原页 loading、error 或 ready；不能假装正在请求模型、制造进度，也不能用可点击的静态截图冒充完整原页。用户界面不出现阶段编号、iframe 或内部 API 等实现术语。

## 4.2 作品身份及 URL 解析

```ts
type ProjectId = 'lawson' | 'courtyard';
type ProjectTab = 'live' | 'archive';
type ActiveProject = { id: ProjectId; tab: ProjectTab };
```

- 注册表中罗森为 embedded-page，入口是 `experiments/lawson/index.html`；庭院为 host-scene。
- selectedProjectId 属于 C2，首次默认 lawson，关闭后保留，刷新回默认。
- activeProject 只有一个权威来源，关闭后为空；其他代码从它派生“庭院现场 / 罗森现场 / 档案”，不维护互相矛盾的 projectId 和 tab 副本。
- 统一公开打开调用为 `open(projectId, tab, trigger?)`，所有入口显式传身份。
- 庭院的 clip/frames 等原资料保留；罗森资料根据已提供内容组织，不为了共用类型虚构视频、过程图或合作履历。
- 罗森 URL 依据 Vite base 和站点文档位置解析。独立链接与第五步都使用同一解析函数，不写死根路径、localhost、私有 GitHub 或第二步的样稿 query。

**验收：**根目录和仓库同名项目子路径下，解析都指向第三步实际原页；独立打开采用新标签及 noopener，作品标题、入口和档案不串用。

## 4.3 C2 正式入口与封面

- 保留 C2 article 的 ID、DOM 身份、阅读锚点、原运镜区间 9.5–10.5 和 stop 10.05；C1/C3 原内容继续使用。
- 添加 LAWSON/罗森便利店与 COURTYARD/庭院习作选择，一次显示当前一份详情。
- 罗森标题、简介及主/次按钮沿用第二步设计：“进入完整网页”“项目档案”。庭院保留“现场体验”“项目档案”。
- 选择页签支持方向键、Home/End、明确焦点及当前项 Tab 顺序。只在当前阅读内容可交互时启用，隐藏或淡出段落不能留下可操作按钮。
- 真实源图作为轻量封面；仅在原 C2 预备/出现逻辑及用户选择时载入相应图片，不创建隐藏原页，不请求罗森模型或 vendor。
- 切换只更新稳定节点内的内容，避免替换整篇 C2 使阅读锚点、流式节点快照或事件引用失效。
- 图片 load/error/decode 与作品身份及资源版本关联。旧图片迟到不能覆盖新作品封面状态；图片失败保留文字、选择及入口。
- 自动导览在用户选择时明确 stop，包含被全局键盘监听排除的 tablist 方向键操作；后续图片回调不得自动重启导览。

**验收：**标题、封面、摘要、入口及可访问名称始终属于同一作品；快速切换和封面失败可恢复；当前选择经过开关作品层、稳定/沉浸切换后仍正确。

## 4.4 容纳检测、稳定阅读与入口身份

新增选择控件后必须复测面板容量，而不是缩小字体或把入口挤到可视区域外。

- 有足够空间时保持现有柱旁定位与魔法文字；不足时沿用稳定阅读，保留所有内容和按钮。
- 封面或作品内容改变后，触发布局测量；自动导览的图像解码记录不能只依赖“同一个 img 元素曾解码过”，应跟随当前资源更新。
- readerFlow 的属性恢复完成后，根据当前选中作品重新应用可用性和选中态，避免恢复旧 disabled 或 aria 状态。
- 主庭院不可用时，仅按实际情况禁用庭院现场；罗森准备态、档案和真实独立链接仍可操作。这不承诺原页在故障设备上一定能运行。
- 稳定阅读水潭段的“进入庭院现场”始终调用 `open('courtyard', 'live', trigger)`，不随 C2 默认/当前罗森而改变。

**验收：**两种阅读模式都能选作品和开档案；容量判断真实、无裁字；水潭按钮和其他原庭院入口仍打开庭院。

## 4.5 统一作品层和大尺寸挂载区

沿用唯一作品 dialog，按作品身份配置内容。影像查看层继续存在，但同一时刻最多一个媒体/作品模态框处于打开状态。

罗森工具栏包含作品名、现场/档案、真实独立打开和返回。其余空间交给稳定挂载区：

| 常规字号视口 | 工具栏 | 内容区域 |
|---|---:|---:|
| 1920×1080 | 56px | 1920×1024 |
| 1440×900 | 56px | 1440×844 |
| 1366×768 | 56px | 1366×712 |
| 768×1024 | 56px | 768×968 |
| 390×844 | 48px | 390×796 |
| 320×568 | 48px | 320×520 |
| 844×390 | 48px | 844×342 |

- 紧凑条件为宽 ≤767px 或高 ≤480px；手机使用简称与完整可访问名称。
- 动态视口高度，工具栏自然高度 + 剩余空间；安全区按设备值处理。
- 200% 字号允许换行，内容高度按实际工具栏计算。按钮至少 44×44 CSS px，返回保持可访问。
- 挂载区无固定比例、最大卡片宽度、scale、裁切或图片式 contain 规则；准备提示只占内容区内适当位置。
- 罗森不显示庭院专用的正常/像素和动效按钮。庭院继续保留原控件和完整构图。
- 第二步左侧全景背景、设计状态菜单、静态截图和 `__STEP2_DESIGN__` 均属于样稿，不移入正式产品。

**验收：**实测容器尺寸符合表中规则；没有移动端横向溢出；同一个罗森挂载节点在页签切换、状态及尺寸变化时保持可识别。

## 4.6 档案按作品分开，保留庭院完整内容

- 罗森使用定稿的介绍、真实封面及功能概览，不虚构未提供的制作过程。
- 庭院保留现有介绍、功能、早期 12 秒视频、原播放/重试入口及两幅早期帧图。
- 档案初始化必须带项目身份，不能继续用一个 initialized 布尔值使后开的作品复用前一个内容。
- 同一次作品打开中的现场/档案切换保留自己的档案滚动；不同作品之间不套用旧滚动值。
- 离开庭院档案或关闭作品时暂停并清理视频、计时器、监听和旧节点引用。迟到的 loadedmetadata/error/play 回调不得更新罗森档案。

**验收：**罗森→关闭→庭院及反向顺序均无标题、封面、视频或滚动串用；庭院视频可以正常播放/暂停，离开后没有持续播放。

## 4.7 主庭院实际停绘

| 当前状态 | 庭院绘制 | 自动导览 | 罗森 iframe |
|---|---|---|---|
| 正常阅读 | 既有主站规则 | 用户选择 | 无 |
| 庭院现场 | 既有庭院体验逻辑 | 停止 | 无 |
| 罗森准备态 | 停止 | 停止 | 本步不创建 |
| 任一项目档案 | 停止 | 停止 | 无 |
| 关闭作品 | 按原设置恢复 | 等待手动继续 | 无 |

重点改造 covered/offscreen/syncLoop/syncAnimation 和所有“live=庭院”分支：experiencePose、applyCamera、鸟的构图处理、体验区域 resize、一次性 renderOnce 及渲染恢复回调均需核对。

使用现有 setAnimating/setSuspended 门控，不只隐藏 canvas，也不把 animation.playing 强行改为 false。主渲染 draw 已有 suspended 检查，优先正确使用它；本步不重做水球、鸟、云影或场景几何。

**验收：**在打开完成并稳定后，用真实 WebGL 绘制/场景回调计数连续采样至少 1 秒，确认罗森准备态及档案没有持续绘制。窗口 resize、图片完成和页签操作不能唤醒被覆盖庭院。不能拿静态 HUD 或单个布尔标记代替计数。

返回后，原播放状态为 true 时可继续；原暂停状态下保持暂停，允许既有有限静帧布局刷新，不得误开启持续播放。导览在两种情况下均由访客手动继续。

## 4.8 返回、焦点、媒体互斥与清理

打开时沿用现有 readingLayout.capture，记录模式、锚点、段内比例、运镜位置及滚动；实际触发按钮单独记录。每次打开只建立一份原阅读快照。

- 模态框打开后背景不参与滚动或键盘交互；保留作品内部应有滚动和触摸，不全局取消所有手势。
- 初始焦点给外层返回；Tab/Shift+Tab 在当前模态内容内合理移动。
- 宿主焦点下 Esc 关闭。为第五步保留“焦点在原网页内时 Esc 交给原页”的 cancel 分支，本步没有真实 iframe 时不冒充已验明原全屏或锁定。
- 关闭后先恢复原阅读，再以 preventScroll 恢复触发按钮焦点；节点失效/隐藏时回退至当前作品选择项或 C2 标题。
- 同视口保存精确位置；尺寸、字号或阅读模式变化后按原 restore 的锚点与比例规则恢复，不机械套用旧 scrollY。
- 项目和影像互斥。切换拥有者时不得重复捕获被覆盖状态、重复恢复或让上一个关闭回调抢走新模态焦点。
- 开关、切页签和 dispose 使用当前实例/代次校验，旧动画、图片、视频、计时器及焦点回调不能重新打开或更新已关闭作品。

**验收：**从沉浸/稳定模式、环境播放/暂停、导览运行/停止四类起点打开再返回均正确；重复开关无多余打开 dialog、后台视频、监听或滚动锁遗留。影像查看、庭院、水潭返回链路仍正常。

## 4.9 给第五步的稳定接口

本步交付以下能力，命名可按现有代码风格落地，实际名字必须写入交接文档：

| 能力 | 用途 |
|---|---|
| `open(projectId, tab, trigger?)` / `close()` | 统一打开、关闭 |
| 当前活动项目只读快照 | 第五步判断是否应创建/卸载罗森 |
| 稳定的罗森挂载 HTMLElement | iframe 填充位置，与庭院画布区域分开 |
| 庭院现场 bounds | 仅庭院构图使用，不误用罗森尺寸 |
| open/change/close 生命周期通知 | 为按需实例提供挂接时机 |
| 宿主状态呈现入口 | 本步 prepared，后续接 loading/slow/error/ready，不伪造原页结果 |
| 真实原页 URL 解析函数 | iframe 与独立打开共用 |
| dispose | 清理宿主资源，后续连同原页实例统一释放 |

第五步的 createLawsonExperience 实例负责真正的 mount/retry/unmount、原 ready/error 观察、全屏/锁定和旧文档回调处理。本步不预加载模型、不插入 iframe，也不把状态演示代码放到正式流程。

**验收：**第五步只需挂接实例管理器及原页状态，不需要重做 C2 数据、容器布局、停绘、返回或重排档案。

## 4.10 验证矩阵

先做必要静态/类型核对，再运行 `npm run build`（含 typecheck），最后从真实主站检查，而不是只测试第二步样稿。

| 类别 | 必测结果 |
|---|---|
| 作品身份 | 默认罗森，两方向切换，先后打开档案均正确 |
| 入口区别 | C2 传选中项目，水潭固定庭院 |
| 懒加载 | 主页面封面、准备态、档案均无罗森 iframe/GLB/vendor 请求；显式独立打开的新页面按原版加载 |
| 原页地址 | 根目录与项目子路径下真实独立链接正确，页面能就绪 |
| 布局 | 1440×900、1366×768、390×844、320×568、844×390；补查 768×1024 与 200% 字号 |
| 阅读 | 容纳检测、稳定/沉浸切换、返回锚点、选择与焦点不丢失 |
| 导览与动效 | 作品选择/打开后导览停止；关闭不自动继续；原暂停不被改成播放 |
| 停绘 | 真实计数证明覆盖时无持续庭院绘制，resize 等事件不误唤醒 |
| 庭院旧功能 | 正常/像素、动效、全景构图、原完整档案视频/帧图仍可用 |
| 媒体互斥 | 同时最多一个打开模态框，退出后的焦点和滚动正确 |
| 故障 | 主庭院不可用时，罗森准备态/独立入口与两者档案仍可访问；封面失败不封死入口 |
| 减少动态 | 宿主过渡关闭，阅读与入口完整；不声称原罗森 JS 已随之暂停 |
| 清理 | 至少 5 次开关与交替打开，无活动媒体、重复监听或滚动锁遗留 |
| 完整性 | public 原 46 文件及重建 dist 副本均与源一致，77/109/115/95 历史封存不变 |

针对新状态管理、身份、异步封面/视频及生命周期做必要的实质检查，复用适用的现有脚本。数值轨迹、场景结构未改时不重跑全部旧几何/材质测试；发现关联问题再扩大检查。
