## 3.5 从实际构建输出验证 HTTP 路径

使用实际 dist 的静态服务，不能仅依赖 dev server 的路径回退来判断成功。建议使用本次专用本机端口；端口已占用时换用空闲端口，不停止其他服务。

至少验证两种部署前缀：

| 模式 | 示例路径 |
|---|---|
| 网站根目录 | `/experiments/lawson/index.html` |
| 项目子目录 | `/Stylized-Dreamy-Flower-Bed-Sky-Island/experiments/lawson/index.html` |

第二个路径是本机模拟部署前缀，不是发布 GitHub Pages。两种模式都指向同一份构建输出，不复制修改另一套 HTML，不改资源相对地址。

检查两种前缀下的 HTML、CSS、JS/vendor 和四个模型请求：

- 实际请求落在相应站点前缀内，没有错误跳到网站根目录或私有 GitHub。
- 资源 HTTP 成功，脚本/样式返回适当内容与 MIME，而不是伪装成成功的首页 HTML。
- 结合磁盘哈希、HTTP 文件信息与真实浏览器解析确认资源正确；不能只查状态码。
- 正常页面请求没有丢失文件或新增外链依赖。若使用缺失路径检查静态服务回退，预期 404 单独标为负向对照，不算成正常路径的失败。

**完成标准：**根目录和子目录均能加载同一原页及本地依赖。未来 iframe 和“独立打开”的相对入口和 base 解析规则明确，正式调用由第四/第五步接回。

## 3.6 独立原网页就绪与默认状态

1. 当前 `window.__LAWSON__.ready === true`。

3. 原 `#fatal` 没有实际显示；原错误优先于曾经的 ready。
4. 画布有有效尺寸，场景已实际呈现，有可检查的首帧和截图。

不得以 HTTP 200、iframe/HTML load、加载条消失或 API 对象存在代替上述条件；不手动设置 ready，不改时钟或启动守卫制造通过。

## 3.7 迁入后的最小实际操作核查

第一步已有完整功能基线，第三步针对“实际构建后的页面能执行”做必要抽查，不重跑所有随机任务和完整交通周期。

根目录页面至少完成：

- 用原时间按钮切到夜晚，观察原场景/时间变化，再回黄昏。
- 用原 LAWSON 招牌灯光开关操作并观察对应反馈。
- 用一个原相机按钮改变视角，再通过原全景按钮回到默认构图；给原补间足够原生时间，不用固定几百毫秒替代等待。
- 屋顶原按钮隐藏/显示，确认原场景或屋顶状态随之变化。
- 短时间观察自动车流，记录实时车辆位置/车轮变化；使用原按钮暂停和恢复，核对实时反馈。

车辆位置采用 `getVehicleState`，不能以 UI 缓存的 `traffic.activePosition` 证明暂停或移动。相机整数投影只作合适精度的比较，避免因原惯性问题宣称所有时机都能精确复位。

子目录页面在独立就绪、默认状态、全部资源路径通过后，再做至少一项原 UI 操作，确认不是只有静态画面。

**完成标准：**原按钮在迁入和构建后有实际反馈，正常路径无未捕获脚本异常或关键请求失败。完整 41 控件、17 类点击的最终集成对照仍留给第七步；真实 iframe 全屏/锁定/输入隔离留给第五/第六步。

| 漏文件、复制差异、构建遗漏、错误路径 | 修正本步迁入或服务设置，复核受影响项 |
