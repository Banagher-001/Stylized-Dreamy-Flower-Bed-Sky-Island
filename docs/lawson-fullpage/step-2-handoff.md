## 2. 第三步执行顺序

1. 核对当前工作区和两仓库版本。保留第一/第二步已有未提交资料；出现与记录不同的实际改动时先查明，不能覆盖。
2. 检查目标目录。若已有不同内容，先核对来源和差异，不强行覆盖。当前第二步结束时目标尚未创建。
3. 按源清单复制全部 46 个文件，保持目录及文件内容。包括 HTML、CSS、JS、vendor、本地 import map 与四个模型。
4. 校验目标逐文件 SHA256、字节、总数与总量，确认没有遗漏、静默改写或加入新的远程依赖。
5. 按当前 package.json/锁文件的项目要求构建，检查 `dist/experiments/lawson/` 的同一套 46 个文件仍与清单一致。
6. 从实际构建输出独立 HTTP 打开原页，核对原 ready/error、原默认界面和关键请求；不能把 HTTP 200 或 HTML load 当作场景就绪。
7. 同时检查根目录和网站子路径部署的资源解析。地址由网站 base 决定，独立链接和后续 iframe 共用同一个解析方式。
8. 记录复制、构建、网络请求、就绪、截图、已知问题及完整性证据。先完成第三步验收，再进入第四步宿主实现。

## 3. 保留原网页的具体约束

原 41 控件、17 类物件交互、各相机、车辆、店员、昼夜、灯光、屋顶、帮助、画质、漫游及原全屏都以第一步基线为准。完整矩阵见 [feature-matrix.md](feature-matrix.md)。

不合并两版 Three.js、不注入桥接脚本、不移除原控制台、不重做原手机界面、不改原 guard/ready/error，也不修补已知碰撞或 R 行为。复制过程中发现问题应先区分原有问题与复制错误。

## 4. 已知问题随交接保留

- 拖动后 R 复位有惯性偏移；漫游中 R 退出可能留下 UI 缓存不一致。
- 起始区域 W/S 平面位移受原碰撞盒阻挡；A/D 和左右 Shift+A 已有位移反馈。
- README 中 N 无实际绑定；帮助中的车体点击没有对应拾取入口。
- 原手机面板及顶部布局、触摸漫游方向控制有局限。
- 减少动态设置不自动暂停原 JS；pauseAll 不停止绘制。
- 真实后台隐藏、物理手机、其他浏览器和硬件 GPU 不属于第一步已完成实测。

详见 [原页问题](original-issues.md)。这些不是第三步复制时可以静默修复的事项。

## 5. 给第四/第五步的设计定稿

- 第三根柱子 C2 默认罗森，庭院可切换；只显示当前一份预览。
- 统一调用 `open(projectId, tab, trigger?)`；作品类型为 host-scene / embedded-page。
- 罗森工具栏常规 56px、紧凑 48px；其他可用空间全部给原页。字号放大自然换行。
- 独立打开与 iframe 指向同一真实原页入口，样稿中的 `?standalone=` 地址不带入生产。
- 罗森现场时主庭院停绘，导览停止；离开现场卸载，返回恢复原阅读/播放设置，导览手动继续。
- 原页错误优先于 ready；iframe load 不等于就绪。原页重试后的新文档重新观察。
- Esc 优先保留原锁定/全屏行为，宿主返回入口保持清楚。
- 庭院故障与罗森入口分别判断。

详细规则见 [设计定稿](step-2-design.md)、[接口契约](step-2-interface.md)。

## 6. 容易误用的材料

设计 HTML/CSS/JS 只属于样稿，不替换正式主站。其全景背景、静态参考区、状态菜单、`__STEP2_DESIGN__` 和独立样稿地址均不进入生产。

样稿静态截图按 contain 显示是为了保全图像，不是正式 iframe 的布局规则。正式 iframe 不使用图片缩放或固定比例。庭院档案的现有视频和帧图在后续保留，不能被样稿的缩略内容覆盖。

第一步封存 109 个文件及旧封存 77 个文件只做校验，不重新生成。不要重跑第一步 finalize.py 覆盖封存，也不要把后续允许的宿主改动倒写进第一步历史基线。第二步另有封存清单。
