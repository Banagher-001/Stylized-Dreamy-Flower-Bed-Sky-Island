## 6. 海浪—帆船连续联动

固定视口、相机、画质、水位、船体响应、阻尼、风力和其余波浪参数，分别通过原 UI 设置波高 0、50、100，观察实际水面与船体。

- 每档先等待自然过渡，再保存连续样本。默认速度条件下，正式采样应至少覆盖 8 个实际 simTime 秒、至少 40 个不同渲染帧的有效样本，并记录墙钟耗时；慢速档按实际波周期扩大时间窗。
- 记录原 simTime、水面/五采样点、船体位置与旋转、波场参数及原安全检查。允许使用 getDiagnostics 和已有对象只读取数；可视画面与遥测相互对应。
- 波高为 0 的平静状态与 50/100 的实际浮沉、俯仰、横摇分别记录。比较连续振幅/轨迹，不把不同相位的单帧高低当作联动或单调增强证明。
- 方向选 0/90/180/270 的代表组合，观察真实波场与船体姿态；水位及响应/阻尼/风力按对应真实效果记录，不臆设每个参数都应单调放大振幅。
- 检查代表强浪/水位组合的有限数值、瓶腔约束及船壳/桅杆，留存实际画面和原安全遥测；不把软件安全布尔值单独当作所有画面绝不穿模的证明。

不修改时间、RAF、原 dt、物理系数、随机数或内部状态，不使用强制姿态使断言通过。原 tick 将单帧模拟推进限制为 0.05 秒，云端低帧率下墙钟时间与模拟时间会不同；等待以实际进度为准，分段采样并保持进度更新。未达到采样条件就记待补核，不凭旧 QA 数值替代。

**验收：**足够长的实际水面和船体轨迹支持联动结论，观察到的饱和/异常/约束边界单列，不承诺穷举全部参数组合。

## 7. 相机、指针与原快捷键

五个原镜头逐个真实点击，等待原补间与实际绘制后记录相机位置、目标及画面。初始已处于某机位时检查到位，不强求每次都有位移；换到其他机位要有实际变化。

真实操作左键旋转、右键平移、滚轮缩放，再使用原恢复镜头按钮观察恢复。记录惯性及原边界，不能用 API 复位掩盖残余漂移。双击瓶子/船体、双击地形、点击灯塔分别检查实际命中与聚焦/灯光效果；双击灯塔如涉及多次原生事件，按真实顺序登记。

键盘至少核对：

- H：场景/普通页面焦点下隐藏与恢复 UI；输入框获得焦点时按原保护逻辑观察。
- Space：场景焦点下暂停/继续；输入框与按钮焦点条件分别记录，避免原生按钮激活与全局处理混算。
- Escape：退出石头/贝壳放置，编辑状态与提示同步，页面仍可操作。

**验收：**真实用户输入与实际相机/原对象响应对应；调试 API 只辅助读取或明确标注的视角准备，不代替射线命中、点击、双击或按键。

## 8. 沙盒放置、撤销与重置

从新文档的原装饰状态开始，选石头并在可放置沙地实际点击，记录新增物件身份、数量与位置；再选贝壳，检查两类物件。验证撤销最近一次放置、继续放置及恢复装饰。

核查拖动与普通点击的区别、Escape 退出、非放置状态点击，以及瓶腔内部/海面等代表位置的原规则。不要调用 addProp/undoProp/resetProps 作为用户操作证明，也不额外发明原版没有的编辑能力。放置上限和未覆盖边界可静态记录，不能称全部地形像素都已测试。

**验收：**新增物件真实出现，撤销和恢复改变实际对象集合，原装饰按原逻辑恢复；不能只凭“已放置”的 toast 判通过。

## 9. 暂停、继续、参数恢复与截图

暂停前后连续取样 simTime、船体和原环境状态，确认模拟冻结，原相机仍可观察；继续后检查正常推进和非异常跳变。全局重置通过原按钮触发，分别检查 12 个参数、画质、机位、编辑/装饰及播放状态。

单独记录：原暂停不会停止 tick/渲染，相机仍更新。这个事实将交接给后续生命周期设计，不能把原暂停按钮当作已卸载、停绘或释放 GPU。

截图以实际成品 captureScreenshot 为准：

1. 点击原截图按钮并接收真实浏览器下载，记录文件名、PNG 类型和字节数。
2. 读取实际 PNG 宽高并检查图像内容不是空白/错误帧，保留像素外观，内容是原 WebGL 场景。
3. 预期宽高为画布 CSS 尺寸分别乘 min(DPR,2)，再取整且至少为 1。1920×1080、DPR 1 时应导出 1920×1080；其他视口/DPR 按同一原规则，不强改成固定尺寸。
4. UI 显示和隐藏后的导出范围按原功能核对，不声称含 DOM 面板。至少补一个不同视口或 DPR 条件，防止偶然匹配原 QA 尺寸。

**验收：**模拟控制和渲染语义分清，重置各项有结果，下载真实生成、尺寸与图像内容符合原规则。

## 10. 尺寸变化、加载异常与就绪信号边界

桌面、窄桌面和手机代表尺寸记录默认布局、控制台滚动、折叠/展开及关键操作是否可达。尺寸变化后等待实际画布更新再测点击，触摸使用浏览器真实输入通道；只有 DOM 合成事件不计作真实触摸通过。

分别核查普通标签切换返回、刷新、新文档默认值、减少动态条件与 WebGL 失败。后台确需记录 hidden 时必须实际观察，不覆写 document.hidden 或手工派发事件冒充。

通过浏览器禁用 WebGL 或真实 WEBGL_lose_context 扩展核查故障，记录错误 UI、原 ready/error、canvas 事件和重新加载后的恢复。原 ready 在丢失后可能保留 true，应作为后续宿主不能单独信任它的依据；不在本步偷偷修复原标志。权限/浏览器无法支持的路径如实列明。

**验收：**默认、故障、恢复与能力限制有区别；原布局问题和原缺少的适配列入原版问题，不提前归因给尚未实施的 iframe。

**验收：**功能结论可复查，范围准确；缺少证据不能写通过，已明确的原问题也不能被“页面能显示”掩盖。
