## 1. 本步范围与执行顺序

执行顺序为：固定版本和保护范围 → 保存完整成品及声明 → 写来源清单 → 准备真实封面 → 构建复制与路径检查 → 独立浏览器代表操作 → 主站不提前加载检查 → 完整性与交接。

第三步只保存独立资源并验证其独立运行。作品选择按钮、档案展示与三作品键盘逻辑由第四步负责；iframe 挂载、状态适配、重试/卸载和阅读恢复由第五步负责。第二步目前未执行，不假设其报告、代码或封存已经存在；这里明确的静态入口可供后续对接，正式容器仍按第二步实际交付落实。

不重构建原工程，不修改或压缩原 HTML，不使用 WORLD_STUB，不将原依赖安装进主站，不修改主站/罗森业务逻辑，不修复第一步登记的原问题，不提交、上传或部署。

验收：本步完成表示“完整原页已保存在仓库工作区并通过独立访问验证”，不等于 Coding 入口已增加、iframe 已接入、已提交 GitHub 或已有公网地址。

## 5. 验证主站构建按原字节复制

使用主站已有 npm run build 检查类型与生产构建，使用本步新建、记录归属的输出目录，避免覆盖现有 dist 或用户准备中的产物。原仓库的 build.mjs 不运行。

当前 vite.config.ts 的 base 为 './'，public 默认作为静态资源复制。须读取实际配置、构建日志和产物确认，不能仅因工具约定就写通过。不得为了存放单文件修改现有代码分块或引擎版本。

必须满足：

```text
原仓库 index.html
  = public/experiments/bottle-ocean/index.html
  = 本步生产构建目录/experiments/bottle-ocean/index.html
```

上式为字节级相等：三处都核对大小与 SHA256。第三方说明同样核对；新增 SOURCE.md 应从 public 原样进入产物。原 HTML 作为独立静态文件复制，不应被当成主站入口重打包、注入主站脚本或替换内联 Three.js。

HTTP 若使用压缩传输，应比较解码后的实际响应正文，不把压缩包摘要与原文件摘要混比。任何 HTML 字节差异都先定位原因，不能以“构建后正常变化”忽略。

验收：主站构建成功，运行文件及声明原样保留，主站 package.json、锁文件、Vite 配置和既有业务输入保持原样。构建环境问题单列，不伪装为原网页功能通过。

## 6. 根路径与项目子路径的真实访问

至少检查下列入口；示例 origin 和 /portfolio-check/ 是本机测试条件，不是已发布地址：

| 条件 | 路径示例 | 必须验证 |
|---|---|---|
| 开发服务 | {origin}/experiments/bottle-ocean/index.html | 正确成品、HTML 类型、正文摘要和真实场景 |
| 生产构建根路径 | {origin}/experiments/bottle-ocean/index.html | 从本步产物提供内容，正文与固定原版相同 |
| 生产构建项目子路径 | {origin}/portfolio-check/experiments/bottle-ocean/index.html | 将产物真实挂载在该前缀下，直接访问并刷新成功，不错误回到网站根路径 |
| 说明文件 | 对应前缀下 THIRD_PARTY_NOTICES.md、SOURCE.md | 文件存在且内容正确 |

子路径测试须真实部署到本机服务器的前缀路径，例如把同一份相对 base 构建产物挂在 /portfolio-check/；不能只更改浏览器地址或输出一段路径字符串。没有必要为了这个测试更改主站的持久配置。

检查 HTTP 状态、Content-Type、正文大小/摘要，以及实际页面身份。200 响应不一定是原页面：若服务回退到个人网站 index.html 或错误占位页，则不算通过。核心检查使用明确的 /index.html 入口，不依赖任意静态服务器都支持目录补全。

使用新浏览器上下文和无缓存条件，观察请求和失败日志，确认原页不需要 GitHub、CDN 或未复制的外部运行文件。已知的受管 Chromium file:// 策略限制不能通过改安全策略绕开；本步主要验收 HTTP，不重复承诺主站文件直开。

验收：开发路径、构建根路径和真实前缀路径均能取得正确原页；独立链接与未来 iframe 可以使用同一个相对入口 experiments/bottle-ocean/index.html。

## 8. 验证主站不会提前运行新作品

保持现有产品源码与作品配置不变。分别在开发和生产条件打开个人网站，代表性浏览到 Coding 区，观察网络与 DOM：

- 没有请求或执行 bottle-ocean/index.html，没有瓶中海洋 iframe，没有隐藏现场实例。
- 本步新封面尚未被引用，不通过它触发原网页或额外场景初始化。
- 罗森路径和现有 Coding 入口继续使用原配置，主站原引擎和业务文件摘要不变。

主站新增静态文件会增加构建产物体积，但未引用的运行文件不会因此自动执行；不把“新增文件”描述成没有任何存储成本。现有页面可能有正常的主站、开发工具或罗森请求，需按请求身份判断，不把它们混算为瓶中海洋提前载入。

验收：本步只增加待调用资源，不改变个人网站当前交互；完整主站/罗森动态回归仍由第六、七步执行，不能以摘要不变替代未来的内嵌回归。
