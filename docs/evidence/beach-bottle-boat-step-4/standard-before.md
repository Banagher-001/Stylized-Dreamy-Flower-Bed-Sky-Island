## 4. 三作品选择器和阅读位置

在现有 C2“交互作品”位置扩展为三项作品索引，继续使用同一个预览区域。保留 C1/C2/C3 的文章身份、位置和石柱关联，不新增石柱，不把三个作品堆成三份长卡片。

选择器沿用深绿、浅色文字、细线边框与选中标记。每项包含英文索引和中文名，按钮点击目标至少 44×44 CSS 像素。桌面优先三列；窄屏允许文字换行，在空间不足或大字体条件下有序换行，所有作品仍完整可发现，不以无提示的横向溢出隐藏选项。

每次切换只更新当前预览、标题和动作归属。保留已停下的导览状态；已有 handover/阅读布局重新测量机制继续使用，读者仍停在当前作品区域，不重置为页面开头或跳去另一根石柱。

键盘行为固定：

| 输入 | 结果 |
|---|---|
| Tab 进入作品索引 | 焦点落在当前已选作品 |
| ArrowRight | 按顺序选择下一项，末项回到首项 |
| ArrowLeft | 按顺序选择上一项，首项回到末项 |
| Home / End | 选择罗森 / 庭院，并移动焦点到该选项 |
| Enter / Space | 原生按钮激活当前选项，不意外打开项目或滚动页面 |
| Tab / Shift+Tab | 从索引进入/返回相邻操作；不捕获整个页面的导航按键 |

当前可交互选择器中只一个 aria-selected=true，只有当前项 tabindex=0，其余为 -1；共享 tabpanel 的 aria-labelledby 随当前作品更新。隐藏文章的 inert、disabled、aria-hidden 沿用原机制，不让不可见按钮进入键盘顺序。

验收：鼠标、实际触摸点按与键盘均可到达三项；快速来回选择也不串图、串内容或改变阅读章节。

## 5. 真实封面、摘要和加载状态

瓶中海洋预览呈现“英文作品索引 → 当前标题 → 真实场景 → 简短说明 → 完整网页/档案动作”的层次。沿用主题的深绿底、浅金标题和细线细节，让原图的黄昏暖色成为作品特征；不把原网页内的控制台复制成卡片装饰。

封面框在三作品间保持稳定尺寸，使用主题底色和完整图像显示。玻璃瓶、船体等关键主体不被随意裁断或拉伸；桌面保留现有预览的阅读容量，小屏可用缩略图配摘要，档案再展示完整大图。

直接引用已保存 PNG，不改原图像素和摘要。封面资源本步导入后应出现在主站构建产物中，按实际内容核对；它属于图片加载，不应触发完整运行 HTML、原 Three.js 或新的 3D 实例。

图片加载、成功、失败归当前图片和作品所有。沿用旧图片监听取消与当前图片身份判断；延迟到达的罗森/瓶中海洋图片事件不得把另一项标成功或失败。失败时有可读反馈，当前标题、档案、独立入口和其他作品仍可用。

若有切换过渡，限于短暂的透明度变化，不动画改变阅读高度；尊重减少动态偏好。小屏/大字体不靠截断正文或过度缩小字样强行维持沉浸布局，继续允许已有稳定阅读模式。

验收：图片有真实内容，加载状态准确；切换过程中预览尺寸和当前作品身份稳定，失败不阻断作品入口。

## 6. 设计瓶中海洋项目档案

档案使用同一作品查看器，明确按独立网页元数据渲染瓶中海洋内容，不进入庭院档案的默认 else 分支。罗森原档案和庭院早期动效片段继续保留。

瓶中海洋档案的内容与版式固定如下：

| 层次 | 内容及设计 |
|---|---|
| 作品索引 | BOTTLE OCEAN / INTERACTIVE WORLD |
| 主标题 | 让一片海，托起一艘船。 |
| 简介 | 拖动镜头绕过玻璃，看浪头托起船身；调整风、浪与水位，再在沙地留下自己的布置。 |

档案只陈述真实已有功能，不新增未经提供的开发经历、制作成绩、客户、奖项或设备性能承诺。封面加载完成不等于原 3D 页面 ready，档案不运行隐藏 iframe。

验收：作品身份、标题、图、三组功能和动作一致；在小屏可读可滚动，罗森和庭院档案不串用。

## 7. 当前阶段的完整网页入口与 prepared 页面

第四步固定采用以下行为，避免阶段之间出现空白或错误场景：

| 作品 | 本步主动作 |
|---|---|
| 罗森 | 沿用“进入完整网页”，继续现有 iframe 与加载/重试流程 |
| 瓶中海洋 | “打开完整网页”进入现有查看器的 prepared 视图；其中“独立打开完整网页”可在新窗口运行第三步成品 |
| 庭院 | 沿用“现场体验”，继续已有主站场景 |

瓶中海洋 prepared 页显示当前作品身份、真实封面/简短说明及清晰的独立打开动作。可用文案：“在新窗口探索完整海岸，调整海浪、切换镜头、布置沙滩。”宿主状态为“可独立体验”，不假装载入、卡在进度条或显示原网页错误。

此阶段主站内不创建瓶中海洋 iframe；prepared 时 aria-busy=false，不显示无效的重试按钮。产品界面不展示“第几步未执行”等开发说明。第五步再沿用同一身份和入口接通实际内嵌现场。

静态独立网页区域和链接按 experience.kind 处理；罗森动态回调仍须携带或验证自己的项目/实例归属。打开瓶中海洋 prepared 前应关闭/卸载旧罗森实例，原状态不得继续更新当前作品。若接口调整确有必要，只做本步身份准确性所需的最小修改，不提前实现瓶中海洋运行器。

所有“独立打开”从同一 entryPath 和现有 BASE_URL 逻辑生成；档案后创建的链接也须取得当前地址。使用真实链接、新窗口及 noopener/noreferrer，保留用户激活；根路径和真实项目子路径均测试。庭院不生成不存在的独立 HTML 地址。

验收：用户能真实独立打开瓶中海洋完整页面，路径与页面身份正确；主站 prepared 状态准确；罗森、庭院仍进入各自原体验。
