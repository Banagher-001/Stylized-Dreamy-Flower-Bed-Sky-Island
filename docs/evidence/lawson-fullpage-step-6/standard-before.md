## 2. 设备和浏览器矩阵

| 覆盖层 | 最低计划 | 证据口径 |
|---|---|---|
| 桌面视口 | 1920×1080、1440×900、1366×768 | 记录实际浏览器版本、CSS 视口及渲染后端 |
| 平板视口 | 768×1024 | 区分实际设备与桌面窗口模拟 |
| 手机视口 | 390×844、375×812、320×568、844×390 | 横竖屏、正常/慢载入/失败状态至少选代表组合 |
| 字号与缩放 | 宿主根字号 200%；实际浏览器缩放 200% | 两者分别测，不能互相替代；父页根字号不继承进 iframe |
| 桌面浏览器 | Chromium/Chrome 主验证；Firefox、WebKit 在可用环境实跑 | 启动实际引擎后判断，不以 UA 替换冒充；WebKit 自动化不等于 Safari 真机 |
| 真机 | iOS Safari、Android Chrome 在实际可连接条件下核查 | 缺设备列“未验证”，不把触摸模拟列为真机通过 |

不做所有条件的笛卡尔积。布局覆盖列出的视口；异常选桌面与小屏代表；强制交叉检查小屏＋错误反馈＋200% 宿主字号、横屏/旋转、浏览器缩放与返回。

**验收：**每项标注实测通过、发现问题、浏览器不支持或未验证。核心宿主验收和物理设备覆盖分别报告，缺证据不出“所有设备兼容”结论。先完成可执行验证，不因暂缺真机停止独立工作。

## 3. 容器、动态视口和安全区

正常字号无额外安全区时，工具栏继续常规 56px；宽≤767px 或高≤480px 为 48px。原页占剩余可用空间，无固定宽高比、最大卡片宽度、scale 或截图式 contain。

在以下状态分别测实际 bounds：loading/ready、slow/error 反馈与重试出现、archive、200% 字号。反馈允许自然增高，不能一律套 56/48px；iframe 高度按实际工具栏和内容安全区计算，宽度扣除实际水平安全区，而非无条件等于 innerWidth。

补测连续缩放、横竖屏转换、浏览器工具栏收放和 visualViewport 变化。等待多帧实际绘制，再检查画面和命中位置，避免把 resize 瞬时空帧当最终结论。CSS env/旋转仿真只算模拟，不能证明物理刘海、底部手势条已实测。

**验收：**宿主无横向溢出；返回、页签、独立打开、重试点击区≥44×44 CSS px，位于安全可达区域；反馈和档案能读完。极短屏或大字号可让反馈/工具区合理滚动，返回始终可达，不缩小字体硬塞内容。原页控件维持原尺寸，不因此宣称全部内页触控目标达标。

## 4. 触摸、键盘和焦点

在移动原文档中实际操作单指旋转、双指缩放、控制台滚动、折叠/展开和按钮点按，观察相机或控件实际变化。浏览器级触摸模拟与真机分开，不仅派发 DOM TouchEvent 作为成功证据。

在父页面中记录 scrollY、阅读锚点/运镜位置，确认操作原页不接管主站阅读；滚动原控制台到边缘也不把背景带走。宿主工具栏能正常触摸操作，档案自身可滚动，不全局阻止所有触摸或缩放。

键盘复核 Tab/Shift+Tab、页签方向键、独立打开/重试可访问名称、原网页快捷键和两种 Esc 焦点。打开先聚焦宿主返回，进入原页后按原逻辑操作；关闭恢复触发项，失效时回退当前作品选择。loading/error 的反馈不能高频重复播报。

**验收：**背景不参与模态交互；焦点可从宿主进入原页并回到宿主，不因反复打开丢失。外层操作可达，原手机无键盘漫游等局限如实保留。只做语义/键盘检查时不宣称真实屏幕阅读器已通过。

## 5. 网络和文档异常

| 场景 | 预期行为 |
|---|---|
| 原页 HTML 请求失败，或返回 404/500 页面 | 按实际可读文档判定是否未正常打开；无原页信号时不得 ready。不能从 iframe load/onerror 直接推出 HTTP 状态 |
| HTML 返回错误文档 | 若导航已完成且明确缺失原页必要结构，可提示“页面未能正常打开”；不伪造观察不到的 HTTP 编号 |
| JS/vendor 请求失败或模块不能启动 | 持续等待真实信号；原错误界面出现则 error，无法确定则 slow，返回/重试/独立打开可达 |
| 主模型或车辆资源失败 | 按原实际 fatal/API/body 信号处理，不把局部资源失败简单写为成功 |
| 慢载入后成功 | loading→约12秒 slow→真实 ready，收起宿主反馈，不改原进度 |
| 慢载入后原30秒 fatal | 原错误显示优先；后来的旧/矛盾 ready 不掩盖 fatal |
| 冷缓存断网、热缓存断网 | 分别记录，缓存能成功运行即按真实结果，不把离线开关本身算失败证据 |
| 嵌入受浏览器/响应头限制或文档不可读取 | 不显示旧 ready；给出诚实的未就绪/不可确认提示及独立入口，不猜测具体根因 |

断网恢复后按原加载结果或显式重试恢复；不增加后台自动无限重试、不自动弹新标签。独立打开只在访客明确操作时发生，也不能保证绕过设备缺少 WebGL 等底层限制。

使用实际 HTTP 响应、网络拦截或浏览器离线模拟；记录失败发生在文档、模块还是模型层、缓存条件和重试路径。原运行文件不为测试改写，不用设置 ready/error 的测试按钮代替实际故障。

**验收：**确定错误与无法确认分开；所有异常有返回和恢复入口，无误报 ready、无限空白且无操作、错误叠层或失效重试。若修复文档识别，仅增加有证据的宿主判断，不用额外预请求猜测真实导航结果。

## 6. 图形异常和两个场景隔离

分别测试：主庭院初始 WebGL 不可用、运行中 context lost/restored；罗森初始 WebGL 不可用、运行中图形上下文丢失。可用 WEBGL_lose_context 时用真实扩展触发，明确属于故障模拟；不把手工 DOM 事件当实际 GPU 丢失。

主庭院失败不连带禁用罗森、两种档案或独立入口。主庭院恢复发生在罗森打开期间，也不能唤醒被覆盖庭院的持续绘制。罗森实际图形失效时，既有 ready 标记不能作为当前恢复成功的唯一依据；按真实事件/当前可确认信号反馈并保留重试，无法确认不伪造恢复。

**验收：**错误归属正确，能返回/重试；恢复无多份 canvas/iframe。罗森活动时主庭院实际连续至少1秒 draw=0；关闭后按原播放设置恢复。不能为加速测试调用原 pauseAll、强制低画质或改原时钟，也不把此环境软件 WebGL 的 FPS 当硬件性能。

## 7. 快速操作和所有者交接

重点顺序：loading 中关开、slow/error 重试后立刻切档案、原页刷新中宿主重试、ready 后连续现场/档案、罗森关闭后开庭院或影像，及反向顺序。

每个正常用户路径先通过现有入口操作；另用明确标注的强制调用覆盖本来因 inert 无法直接点击背景控件的竞态，不把人工注入描述成新产品入口。

完整进入/退出至少10次；同任务或加载中取消至少20次，可复用缓存，不要求每次重复下载。检查最多一个罗森 iframe、最多一个打开模态框、当前标题/档案身份正确、旧 load/error/timer/焦点回调不覆盖新拥有者。

直接由另一查看器接管时沿用首次有效阅读快照，不在被覆盖状态再次 capture；真正退出后从新入口打开再建新快照。旧 close 事件不能恢复背景或抢走新模态焦点。

**验收：**无双实例、重复打开、幽灵媒体、残留滚动锁或旧回调。用旧实例计数及资源持有情况检查清理，不以“DOM 不可见”代替卸载，也不承诺浏览器立即归还 GPU 内存。

## 8. 后台、页面返回和减少动态

分别在 loading、ready、error 时实际切出/返回标签或最小化；记录 document.visibilityState 和真实 visibilitychange。没有实际 hidden 变化就记未覆盖，不覆写 document.hidden 或手工发事件冒充。

默认保留原实例和原页自己的后台行为，不因普通标签切换重建并丢失原状态；若浏览器实际丢弃文档，按新文档重新观察。返回重新核对当前状态，不自动继续主站导览、不更改原环境播放选择、不重复挂载。计时器被节流后的等待状态要真实，不把节流本身当确定失败。

检查同标签导航后浏览器返回，记录 pageshow.persisted 是否为 true。BFCache 恢复需重新核对已有实例和状态；整页重新加载则按原初始规则，不承诺新增跨刷新保存。

减少动态开启/切换时，宿主遵循已有导览与过渡规则。原 CSS 减少动效不代表原 JS 场景已停止；iframe 打开时的原后台绘制结果如实记录，不通过 pauseAll 伪装停绘。

**验收：**实际返回后身份/界面不串用、无重复 iframe、退出仍有效、导览不自启；离开 live 后旧实例停止。原页仍打开但标签隐藏的原有绘制行为单列，不声称宿主已经实现原 JS 后台暂停。

## 9. 全屏、鼠标锁定和拒绝路径

补测支持/不支持/请求拒绝、旋转和尺寸变化中的全屏退出、锁定中退出、切档案或销毁时释放。通过原按钮和真实用户手势请求，真实浏览器 Esc 退出；保留原页焦点/宿主焦点两类行为。

锁定从所属子文档读取，不以父文档 getter 为 null 判断失败。全屏不仅看属性，还等多帧实际场景绘制后确认画面和控件。浏览器不支持某能力时，如实显示能力差异，场景其他操作及宿主返回仍可用；不加不存在的 pointer-lock Permissions Policy 指令。

**验收：**权限拒绝不锁死宿主或阻断其返回；退出仅释放本实例持有的锁定/全屏；清理调用失败也能移除实例。不得把模拟触摸、UA 或 DOM Esc 当作 Safari/Android 原生权限验证。

## 10. 开发 HMR 和最终销毁

在独立临时工作副本运行真实 Vite，分别于 loading/ready/error 触发实际模块热更新。记录旧实例、计时器、监听、canvas、模态框与滚动锁的清理，以及更新后重新进入是否正常。测试用文件改动留在隔离副本，原46运行文件和历史封存不改。

CSS 热更新和实际触发模块 dispose 的更新分开，不用直接调用 dispose 代替整个 HMR 流程。若采取开发整页刷新，需明确且能稳定恢复，不能留下已经销毁的空宿主。

**验收：**每次旧管理器终止后不再更新状态或创建 iframe，更新后只有一套当前实例/主站资源，页面可重新操作。不能将此开发结论等同发布产物所有路由销毁流程已穷举。

## 11. 修复和回归顺序

1. 执行基线、设备能力实测和原页/内嵌对照。
2. 宿主尺寸、字号、安全区与触摸输入。
3. 网络/文档/图形异常与原生权限。
4. 竞态、所有者交接、后台/导航返回及 HMR。
5. 按复现问题最小修复，跑直接关联回归，再做必要核心冒烟。
6. 最终构建、资源校验、证据和第七步交接。

每个修复绑定可复现案例、预期结果和验证范围；没有问题则保留现有实现。通过的第五步用例不全部重复，只有本步改动影响或尚未解决的关联问题才重跑对应项。不同版本结果复用须记录准确构建及差异，不把旧截图当新构建通过。
