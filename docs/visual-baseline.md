# 第一步视觉与工程基准

> 本文保留第一步验收时的基准。第二步已替换验证方块并调整相机；当前构图与参数见 [第二步构图记录](step-2-composition.md)。

## 范围与完成定义

本阶段建立可复现的 TypeScript / Three.js / Vite 工程，交付固定正交镜头下的地面、验证方块、初始色板、正常 / 像素显示模式和方形响应式页面。

以真实浏览器渲染、依赖恢复、严格类型检查、生产构建、产物预览与热更新验证作为完成依据。后续步骤由用户逐步确认，不在本阶段制作喷泉、石柱、人物、花草、水面动画或最终滤镜。

## 参考画面的视觉方向

依据对话中的方形庭院参考图：高俯视固定镜头；黄绿地面；奶油色石头亮部；蓝青色暗部；深青绿树影；浅蓝与深蓝组成的水面；少量粉紫花朵。画面以清楚的大色块为主，碎小细节用于点缀。

风格由构图、造型、光影与采样共同形成。像素预览只验证采样机制，第一步的纯色地面和方块不代表最终美术效果。单张参考图无法证明原作者使用的具体引擎与材质技术。

## 相机与布局

- 正交相机，位置 `[8, 12, 8]`，目标 `[0, 0.6, 0]`，可见垂直范围 `8.5`。
- 地面和方块只用于验证投影、明暗和构图稳定性。
- 相机固定，不自动旋转，不绑定轨道控制。
- 方形画面完整显示，主体居中，页面使用自然文档流。
- 桌面按视口宽度、可用高度和最大尺寸约束画布；手机保留边距。
- 较矮的横屏允许页面纵向滚动，优先保持方形比例和完整内容；所有已验证尺寸均不应横向溢出。
- 第二步依据喷泉、石柱与道路重新确定镜头参数，本阶段参数是验证起点。

## 渲染机制

- 显式使用 sRGB 输出与 `NoToneMapping`，避免隐式色彩配置。
- 使用基础 Lambert 材质、半球光和方向光。临时方块使用暖、冷两种基础材质，以检查朝向面与明暗；最终光照与树影在第三步制作。
- 正常模式 DPR 上限为 2；像素模式 DPR 为 1、内部尺寸比例为 0.5。
- 像素模式使用 `image-rendering: pixelated`。正常模式不启用像素放大。
- 相机范围独立于采样比例，切换分辨率不改变场景构图。
- 不在本阶段加入色阶压缩、抖动、Bloom 或昂贵的反射。
- 页面文字、模式按钮和色板使用 HTML / CSS，独立于 WebGL 画布。

## 生命周期与故障处理

- 每次初始化只创建一个画布、一个动画循环。
- 尺寸变化使用 ResizeObserver，并更新投影和内部画布。
- Vite 热更新清理监听器、ResizeObserver、动画循环、渲染器和场景资源。
- WebGL 初始化失败时显示可阅读的提示并禁用模式切换。
- WebGL 上下文丢失时暂停绘制，恢复后重新调整尺寸并继续绘制。

## 阶段验收规则

1. `npm ci` 按锁文件成功恢复依赖，不改变锁文件内容。
2. `npm run build` 同时通过严格类型检查与生产打包。
3. 开发和生产预览都真实显示地面、方块与阴影，不以 HTTP 200 或端口存活代替渲染验证。
4. 两种模式切换正常，像素模式内部尺寸约为显示尺寸的一半；高 DPR 下也满足此条件。
5. 宽屏、窄屏、手机竖屏和连续尺寸切换保持方形，无横向溢出。
6. 配置修改能触发热更新，页面保留一个画布；还原修改后恢复原始效果。
7. 应用无未处理异常；生产预览无资源加载失败。
8. 提供实际截图和明确的检查结果，不把后续风格与性能目标记为已完成。
